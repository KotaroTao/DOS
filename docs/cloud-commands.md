# 戦闘命令と差分保存

2026-10-31の第一段階。戦闘の選択をサーバーで計算・確定する。探索・街の状態は従来どおりブラウザで計算し、確定済み記録からの差分を送る。全操作のサーバー計算への移行は未完了であり、探索・街の命令実装は別の作業になる。改造クライアントの完全な防止は保証しない。

## 戦闘

`claim.actionCommands`がある接続では、`command`要求に行動者UID・行動・技のキー・対象のside/UID・道具の所有者/袋の位置と、戦況を照合する手番・乱数位置・識別子を渡す。セーブ全体・人業や道具の能力値は渡さない。サーバーは保存された人業・品・習得技・対象候補を使い、既存の`combat.js`で結果と次の手番を計算する。DBの更新番号・要求ID・接続の占有検査を通り、確定した結果だけを描画する。通信が遅い場合は結果を待つ。

選択した命令は、保存準備・送信待ちの前に`dos-cloud-choice:<user>`へ同期保管する。実際の送信前には従来の`dos-cloud-pending:<user>`へ要求IDと本文を保管する。再送ではID・内容を変えない。成功時は選択キーを先に消し、送信待ちキーを後に消す。途中終了では未送信の選択、または送信待ちの同じ要求から再開する。確定できない選択が残っている間は、選択を捨てて古い保存へ戻る案内を出さない。別端末の競合や認証の復旧が解決するまでは進めない。

返答は描画用の結果・次手番・通信基準の更新をそれぞれ差分化する。JSONBとブラウザでオブジェクトのキー順が異なっても、同じ基準を作る。CompressionStream/DecompressionStream対応の接続には、gzipをBase64で包んだJSONを返す。包みの増加分も比較し、小さくなる場合だけ採用する。既存のHTTP/CORS設定を使い、Content-Encodingのゲートウェイ依存を避ける。展開後本文は64MiBまで。小さな返答・非対応接続は従来JSON。

## 通常保存

再開時の補正・能力再計算後は一度だけ同期してから操作を許可する。旧方式の未完了手番を進める場合も、通信基準をサーバーの確定済みグラフへ更新する。

差分は「最後に準備した記録」ではなく「サーバーから成功応答を受けた記録」を基準とする。送信列の実行時にWorkerで差分を作るため、準備中に進んだ基準を取り違えない。差分の方が大きければ全体を送る。同一なら送らず、対応する端末チェックポイントだけを片付ける。再送は作り直さず同じ本文を送る。

受信側は複製したグラフへ差分を反映し、参照グラフと保存の形式を検査してから通常のDB更新へ渡す。危険なキー、過大な差分、配列範囲外の操作を拒否する。端末の復旧記録は単独で復元できる完全な記録のまま残す。初回保存・大幅な変更・旧接続では全体保存も残る。

## 互換性と範囲

- APIは旧`save`/`turn`/`battle`要求を引き続き受け付ける。新しい機能はclaimで確認する。
- 保存頻度・結果の式・乱数・品の個体と共有参照は変えない。戦闘の結果表示にはサーバー確定を必要とする。
- 探索・街・宝箱・出来事の選択そのものをすべてサーバー命令化したわけではない。これらの既存の端末保管・再送保護は維持する。
- 初回の移行や構造が大きく変わった保存では、全体送信になる。毎回の全体送信を避ける方式であり、全体送信を禁止する方式ではない。
- 今回は既存RPCと保存テーブルを使う。DB内部のセーブ全体の読み取りや、通常保存での重複した引数転送の削減は別途対応する。
- 古い別端末が長く進行した後は手番・乱数位置も照合し、古い選択を適用しない。未確定の選択は自動破棄せず、明示的な退避後に最新記録へ再開できる。

## 検査と計測

`node tools/cloud/commands-check.mjs`で差分復元、共有参照、キー順、危険なパス、選択の先行保管、入力検査、攻撃・防御・逃走・回復技・道具を確認する。`database-check.mjs`では実SQLとEdgeを使い、命令の確定・同じIDの再送・同じIDの選び直し拒否・差分保存を確認する。

`python3 tools/cloud/commands-browser.py`は8001番のゲーム、8002番のtest-serverが必要。1,000品の検証用記録で、要求は数百バイト・返答約25KB（この試験条件の値）を確認。返答を一度失わせても同じ要求を再送し、再起動後の敵HPと所持品数が一致する。実プレイ全体の削減率や回線遅延は別途実測する。

「保存と通信の計測」は`command`も集計する。圧縮した応答は、gzip-Base64を包んだAPI本文のUTF-8バイト数を数える。HTTPヘッダー・HTTP圧縮・画像・認証・DB内部通信は含まない。

多種類の品を持つ場合、保存形式の辞書への中間挿入で番号がずれても、内容と順序が同じ辞書項目を探して差し込み箇所だけを送る。辞書の重複・並べ替え・DBのキー順の違いも復元検査する。
