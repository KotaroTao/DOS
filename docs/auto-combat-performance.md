# オート戦闘の描画負荷

行動選択・戦闘結果の表示・カード更新・Canvas描画・音の準備を、実ゲームの連続オートで計測する。エフェクト単体の処理時間だけで評価しない。

## 変更

- `auto-planner.js` は戦闘の共有参照を保った複製をWorkerへ送り、`auto-worker.js` が従来と同じ `decideAuto` を実行する。開示済みの属性/抵抗、手がかりの補正、解放済み・オート有効の技を渡す。結果の対象は本体の参照へ戻す。
- 応答時に戦闘・現在の人業・入力状態・オートONを確認する。作戦設定の変更やシートを開いた場合は選び直す。Worker不可/故障時は従来の同期経路へ戻す。
- 味方カードは変化していないものを再生成しない。HP/MPだけなら数値・充填率・瀕死表示を更新し、カードDOMを維持する。
- 斬撃素材の色変換を小分けにして描画へ時間を返す。音のバッファは戦闘開幕から小分けに準備する。
- オートの行動待ち中も60fpsを目指して描画する。全フレームの間隔が22msを超える状態が続くと軽量化し、安定後に復帰する。ユーザーが選んだ固定画質を優先する。打数・移動速度・数値・表示尺は変えない。

## 計測

Chromium、390×844、6人、通常画質、20秒の連続オート。クリック準備の時間も採取に含む。音の初期化済みの戦闘を比較し、関数ごとの時間とrequestAnimationFrame間隔を記録する。

| 項目 | 変更前 | 変更後 |
|---|---:|---:|
| 主スレッドの行動選択・最大 | 24.3ms | Workerへ移動（同期復帰0回） |
| 戦闘中の音準備・最大 | 8.5ms | 0.1ms |
| カード更新・95百分位 | 0.8ms | 0.5ms |
| フレーム間隔・95百分位 | 16.7ms | 16.7ms |
| フレーム間隔・最大 | 33.4ms | 33.4ms |

測定JSONは `docs/performance/auto-before.json`・`auto-after.json`。この端末での平均的な滑らかさは元から良く、主な改善は描画と競合する処理の削減。全端末でフレーム落ちがゼロになる保証ではない。最初の音声起動を含む別測定では約83msの間隔も記録したため、音声起動と継続中の戦闘を区別して調べた。

## 次手先読みの公開後の回帰と切り戻し（2026-11-04）

#1458で追加した演出中の次手準備は、公開後に利用者の実機で演出のかくつき・音切れが大幅に悪化したとの報告を受け、変更前へ戻した。上記の過去の計測値は利用者端末での滑らかさを保証しない。

演出中の主スレッドでの戦闘状態の複製・全入力の整列/文字列化・Worker送信に加え、作戦Workerと保存Workerが同時に動く構成だった。描画・音声との競合が疑われるが、原因の断定には問題端末での計測が必要。通常のCPU遅延試験やフレーム計測だけでは端末全体の負荷や実際の音切れを検証できていなかった。

今回の切り戻しでは先読みだけでなく、同PRの固定待機の除去・保存準備の順序変更・技一覧の共用も撤回し、`game.js`・`autoforecast.js`を公開前の`aa659063`と同一にした。作戦は従来どおり手番の開始時に計算する。効果音・斬撃・ダメージと撃破表示の消去など、#1456までの修正は保持する。新設済みの心得ID `t_auto_prepare` は残し、説明を変更した。

追加の見直しは、仕事の重ね合わせではなく、作戦用データの削減とした。作戦は道具使用や装備変更を選ばないため、人業の`items`と画像の`photo`を、複製・Worker転送より前に省く。`refSerialize`の任意の`omit`で一度の走査中に除外し、別の全体コピー・整列・JSON照合は行わない。装備中の品、能力、状態異常、使用可能技、図鑑の開示情報は保持する。通常のセーブやクラウド送信は従来どおり全項目を保存する。

検査は、所持品6,000個の追加前後で作戦用データ要素数が同一、装備と袋が同じ品を参照する通常/圧縮保存の復元、入力/乱数/作戦の不変、40秒の実ゲームオートで演出中の作戦開始が0件であることを確認する。最新iPadの通常/倍速で悪化したとの利用者報告を受けた修正だが、その実機での改善確認は未実施。音切れをフレーム間隔だけで解消済みとは判断しない。

## 描画中の再変換と高リフレッシュレート（2026-11-05）

前回の切り戻し後も、最新iPadの通常/倍速で悪化が続くという報告。公開サイトは`8bb7fb10`を配信していたが、利用者の実行中の版は未確認。前回の先読みだけを原因と断定しない。

再現できた別の問題は、斬撃の色変換キャッシュが6種類しか保持しないこと。通常属性6色と薙ぎ払い6色を巡回すると、2巡目にも12回の`getImageData`と画素変換が発生した。タイマーで小分けにしていても、描画中の読み出し・割り当て・大量のタイマーは残っていた。修正後は同じ試験で0回。色付きの18コマを出荷前に生成し、実行中は画像を読むだけにした。

- `tools/effects/build-physical-tones.py`で元のRGBAから旧式と同じ式・透明度で25色を生成。lossless WebPで合計約6.5MB。全色を起動時に取得せず、使う色のみ取得し、利用時にSWの画像キャッシュへ保存する。元のWebP復号とCanvasの乗算丸めの差を含め、可視部分の色差は検査の許容範囲内、透明度は一致。
- 色付き素材の保持は最大16件（約20.3MiB）。未復号・読込失敗時は元素材を使い、描画内で同期復号や画素変換をしない。構えでは選ばれた技の色だけ準備する。
- 主演出のCanvas描画を60fpsまでに制限。120Hz等の画面でも描画回数を増やさない。打撃の移動速度・打数・音・ダメージ/撃破表示の400ms消去・技の全体尺は変更しない。低いfpsからの追い付きで連続描画もしない。
- 更新時にオートを先に止め、確定処理中は再読込せず、保存完了後に更新。更新待ち中に次の命令が送られ続ける経路を避ける。

設定→「音声の診断情報を表示」で次を読み取れる。個人の記録や所持品一覧は含めない。

|項目|確認すること|
|---|---|
|`version` / `viewport`|端末で実行中の版と画面条件|
|`combat.displayFrames`|戦闘中の最大フレーム間隔、34/50ms超の回数|
|`combat.paintedFrames` / `skippedPaints`|描いた回数と上限によって省いた回数|
|`scheduler`|音声予約の最大間隔、360msの予約範囲を超えた回数、中断通知|
|`sfx`|効果音生成の最大時間、生成数、バッファ容量|
|`materials`|色素材の要求数、保持数、復号済みの容量|

これらは実行処理の診断であり、スピーカーからの実際の音切れを直接検出するものではない。利用者のiPad実機での解消は未確認。高リフレッシュレートの単体試験、25色の巡回・保持上限・透明度と色、24条件の結果消去、4条件の5連撃、音声の再起動/無音/初期化失敗の復旧、診断画面に意図的な450ms停止が残ることを検査する。

```sh
python3 tools/effects/tone-cache-browser.py
node tools/performance/auto-frame-check.mjs
node tools/performance/update-auto-check.mjs
python3 tools/performance/battle-diagnostics-browser.py
AUTO_TABLET=1 AUTO_UNCAPPED=1 AUTO_REPORT=/tmp/auto-tablet.json python3 tools/performance/auto-combat-browser.py
```

## 実機の時系列（2026-11-05）

再読み込み後、通常どおり戦闘し、症状が出た直後に設定→「音声の診断情報を表示」を開く。計測の開始操作は不要。再読込・ページ終了で記録は消える。JSONの`timeline`は端末内だけで保持し、自動送信・保存はしない。

- `recent`: 8ms以上の処理を直近256件まで記録。`dropped`は上限で消えた件数。`slowest`は遅い32件を別に残す。`summary`は全呼出しの回数・合計・最大。
- 全時刻はページ読み込み基準の`performance.now()`ミリ秒。`startMs`から`durationMs`までを比較して、同じ時間帯の停止と処理を照合する。
- `sync`: 主スレッドの同期区間。Canvas全体、味方カード、行動開始、効果適用、戦闘計算/結果反映、作戦複製/転送、保存転送/代替処理、効果音生成、BGM予約。入れ子は重複するため合計してCPU時間としない。
- `wait`: 作戦Worker・保存Worker・戦闘確定全体の経過時間。通信・待機・構えなどを含み、CPU占有時間ではない。
- `gap`: 34ms超の戦闘rAF間隔、150ms超の100msタイマー/70ms音声予約の間隔。タイマー自体の周期も含む。画面状態のフラグは採録時の直近状態。
- `mark`: タブ表示/非表示。非表示中と復帰直後のフレーム/監視タイマー間隔は除外する。

Safariでも専用のLong Tasks APIなしで動作。ブラウザの描画合成・GPU完了・GCの内訳や、スピーカーの音切れそのものは未計測。処理区間と遅延が重なっても、単独原因と断定しない。記録には認証情報・セーブ・所持品・戦闘本文を含めず、効果音の識別名のみ付ける。
