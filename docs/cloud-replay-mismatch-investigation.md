# 戦闘終了の記録照合が失敗する問題（2026-11-03）

## 原因と再現

端末は命令ごとにWorkerで記録を復元するが、サーバーは開始地点から命令列を一括再生する。召喚では新しい魔物の `mon`、`affinity`、属性攻防のオブジェクトが台帳を参照する。毎手の復元を挟む端末では過去に生成された魔物の定義は独立した写しになり、一括再生では同じ台帳の定義を共有したままになる。

固定乱数123、HP1000のゴブリンに召喚を設定し、毎手の結果と命令列の一括再生を各選択後に比較すると、旧実装では2手目に不一致となった。復元後の全フィールドの値は一致し、参照の共有だけが異なった。monだけをそろえても7手目にはaffinityの共有が異なるため不一致になった。既存の検査には召喚を伴う長い戦闘がなかった。

## 修正

照合と確定記録の正規化で、魔物の読み取り専用の定義 `mon`・`affinity`・`elemAtk`・`elemDef` をそれぞれ個体ごとの写しにそろえる。内容は変更しない。隊・対象・袋などのゲーム上必要な共有参照は引き続き検証する。戦闘式・乱数・命令列・ルール識別子は変更しない。既存の開始記録と履歴も同じ方法で再生できる。

復旧時は「冒険の記録を読み直します。保存済みの戦闘の続きから再開できます。」と表示し、既存の退避・再読込ボタンを使う。未送信の操作の保護は維持する。心得 `t_battle_ledger` に再開案内を追記。

## 検証

`tools/cloud/ledger-check.mjs` に召喚を繰り返す戦闘の各選択の一致と終了、HP改変・隊の共有参照破損を引き続き検出する検査を追加。既存の大容量の袋・再送・権限・復旧・終了検査も実行する。利用者の本番記録・ログは取得していないため、この再現経路以外の事例まで同じ原因とは断定しない。
