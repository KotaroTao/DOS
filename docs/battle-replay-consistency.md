# 通常プレイ中の再計算エラーの調査

2026-11-02、通常プレイ中に「端末と保管先の計算が一致しません」が表示される報告を調査した。この画面だけでは、命令の計算不能・一手のハッシュ不一致・戦闘終了時のハッシュ不一致を区別できなかった。

## 確認した不具合と修正

`cloud-save.js` はWorkerの計算が失敗した場合、B方式ではサーバーの `ledger-preview` で補助計算する。従来は補助通信の失敗も末尾の `.catch(() => null)` で消し、計算値が得られないことをハッシュの不一致と同じ `cloud_replay_mismatch` にしていた。補助通信には通常の自動再試行もなかった。Workerが利用できなくなってnullを返す場合も、不一致としていた。

修正後は、Workerの例外・nullから補助計算へ移り、補助通信も同じ命令ID・同じ本文で再試行する。認証失敗・競合・一時的な障害が続く場合は元の理由と選択を残す。旧接続で端末計算が完了できない場合も、計算不能として再接続し、実行できなかった照合を「不一致」とは呼ばない。

本当に一手・戦闘終了時のハッシュが異なる場合の停止は維持する。未確定結果の先行表示、選択の変更、照合の省略はしない。通常の通信回数や表示時間は変えず、補助計算へ移った時だけ再試行する。

## 検証

- 修正前のコードへ新しい回帰検査を適用すると、Worker失敗と補助通信503の後に `cloud_replay_mismatch`（409）で失敗した。
- 修正後はWorkerの例外・null、補助通信503・切断から同じ命令で復帰し、追記は1回。ACK前の状態不変を確認した。
- 認証401・競合409・継続する503は元のエラーと選択を維持する。本当の終了時不一致も引き続き止める。
- 既存の `ledger-browser.py` に、Worker非対応時の補助計算へ最初だけ503を返す検査を追加した。実際のゲーム・Edge・SQLを使って復旧と終了まで通す。`DOS_BROWSER=webkit` でSafari系でも実行できる。
- 調査時は37職を含む隊と各技の独立した戦闘条件を比較した。951技の有効な戦闘ケース（計2,841手）では、一手ずつの計算とまとめた再生が一致した。同じ入力をSafari系WebKitとNodeで比較しても一致した。この結果は、利用者の実際のセーブや遭遇条件すべてを再現したものではない。

```sh
node tools/cloud/commands-check.mjs
node tools/cloud/metrics-check.mjs
# 8001番のHTTPサーバーと8002番の tools/cloud/test-server.mjs が必要
DOS_LEDGER_NO_WORKER=1 python3 tools/cloud/ledger-browser.py
DOS_BROWSER=webkit DOS_LEDGER_NO_WORKER=1 python3 tools/cloud/ledger-browser.py
```

利用者の添付画面がこの誤判定の経路だったかは、画面だけでは断定できない。別の原因による実際の不一致を見逃さないよう、保存と通信の計測JSONへ `replayChecks` を追加した。Workerから補助計算へ移った回数・補助通信の失敗試行・一手の計算不能・一手の不一致・戦闘終了時の不一致を分ける。種類と回数だけを端末内へ保存し、セーブ・認証情報・選択やエラーの本文は含めない。自動送信もしない。

心得 `t_replay_connection` を追加した。
