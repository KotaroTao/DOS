# 無限迷宮の仮想通し試験（2026-10）

## 目的と到達の定義

通常の1階開始から50階に到着する出撃を約10%、100階に到着する出撃を約2%にするための調整。到着はその階の主との戦闘前。本番に確率で全滅させる処理は入れない。

実プレイヤーの成功率を保証する試験ではない。入口の選択、永続強化、編成・借用・装備の判断で結果が変わる。以前の `stress.py` は固定レベルの10階区間比較であり、この通し試験の分母には含めない。

## 実行する処理

`tools/infinite/fullrun.py` が本物のブラウザーでゲームを読み込み、配信ファイルを変更せず演出を省き、操作を自動で選ぶ。各出撃は別のブラウザー・保存領域を使い、種を固定する。

- 入口の実際の3択から6職を選び、Lv1・通貨0・持ち込み0で開始。
- 実際の盤面を生成し、既知の壁をたどって近い未公開札へ進む。未公開の中身で進路を選ばない。基本は階全体を探索。罠・毒の歩行・落下・泉・死体・出来事を処理。
- 実際の `startBattle` と `Battle`、ゲームのオート戦闘、戦果、戦闘経験値、宝箱、融合、勝利後回復、階移動効果を使用。
- 回復・使用・個別購入・売却・最適装備・上限解放・魂の強化・主との戦闘も実処理。袋50個・各風だまりの購入3個を適用。
- 回復役を残して上位職へ交代する。交代前に手持ちの✦Soulで育て、旧魂のLvの8割に届かなければ延期。サブ魂は空き枠に宿し、習得済みの戦闘後回復などを優先して借りる。
- 回復は実際の野営呪文を使用。大量試験では全回復の最少MP探索を省き、既存の貪欲法で合法な呪文の手順を選ぶ。回復量・消費MP・状態異常の処理は変更しない。

画面の通知・宝箱の開封者・出来事の選択を自動で処理する。出来事は「推奨」表示、次に危険表示のない手を優先。黒い泉は飲まない。戦闘中の道具使用・個別の手動戦術・逃走・任意帰還は行わない。回収人・灯番の利用判定は実装の `infAtRest` と同じく風だまりの階。熟練者の最適解を探索するAIではない。

## 基準となる本編の進行

基準 `chapter8` は、第八章までの本筋 w02〜w33 の「極の永続強化」を取得済みとする。無限迷宮の解放だけで全部取得済みになるわけではなく、比較条件として明示的に固定したもの。開始時の永続強化は HP+30 / MP+25 / ATK+8 / VIT+6 / AGI+6 / INT+6 / PIE+4 / LUK+4 / 会心+4%。結社・本編の魂・装備・通貨は持ち込まない。

`all` は現在実装されている極を全取得した感度確認、`none` は極なし。基準外の結果を基準条件の到達率へ混ぜない。

## 調整

本編の魔物の強さの素を、そのままLv1開始の無限迷宮へ流用していた。補給制限後の通し試験では中盤までの脱落が多く、深層の1戦だけを見て全階層を強化する方針は採らなかった。

`src/abyss.js` の `infEnemyMul` を無限迷宮の `power` に掛ける。

| 深さ | 本編由来の強さの素に掛ける補正 |
|---|---:|
| 1〜20階 | 0.70 |
| 21〜50階 | 0.70 → 0.80へ連続的に変化 |
| 51〜100階 | 0.80 → 0.95へ連続的に変化 |
| 101階以降 | 0.95から1階につき+0.006 |

推奨Lvによる敵の成長に加え、20階から補正自体も増す。100階以降の追加上昇は長期の無限進行への対策であり、到達率の校正は100階まで。階層の境界で不連続に難しくしない。本編・成長報酬の式・技・補給3個・袋50個には変更を加えない。

罠の基礎ダメージ `(5 + 階数×3 + 乱数) × Lv補正` は、本編の短い迷宮を前提にした式だった。無限迷宮では階数側を5階分で止め、推奨Lvの補正で深くなるほど成長させる。100階では階数項が約305から約20に戻り、通算階数と推奨Lvの二重増幅による満タンからの全滅を減らす。即死罠・異常・解除率は従来どおり。

## 結果

最初の50種（20001〜20050）を使った探索的比較と、追加の100種（40001〜40100）で罠の問題を調査し、罠修正後の100種（80001〜80100）で敵を再調整した後、強め候補の200種（100001〜100200）で50階7%・100階1%と厳しめだったため緩和し、未使用の200種（120001〜120200）による最終検証を分離する。試験打ち切り・操作上限・エラーは全滅に換算しない。圧縮した原記録 `infinite-fullrun-data.json.gz` の各 `cohorts` 内の `rows` に出撃ごとの結果、階層の状態、最後の戦闘、選択を保存する。

採用設定の最終検証は200出撃すべて完走（全滅194・100階到着6）。操作上限・エラーによる除外は0。

| 到達階 | 到達数 / 出撃数 | 到達率 | 95%信頼区間（Wilson） |
|---|---:|---:|---:|
| 5階 | 190 / 200 | 95.0% | 91.0〜97.3% |
| 10階 | 184 / 200 | 92.0% | 87.4〜95.0% |
| 20階 | 155 / 200 | 77.5% | 71.2〜82.7% |
| 30階 | 95 / 200 | 47.5% | 40.7〜54.4% |
| 50階 | 23 / 200 | **11.5%** | 7.8〜16.7% |
| 75階 | 9 / 200 | 4.5% | 2.4〜8.3% |
| 100階 | 6 / 200 | **3.0%** | 1.4〜6.4% |

目標の10%・2%はどちらも区間内。特に100階は6件で誤差が大きく、達成率を正確に2%へ校正できたとはしない。この200種を見てから追加調整はせず、実プレイの独立した記録で次の調整を判断する。

| 比較条件（最終検証とは別集計） | 試行数 | 50階 | 100階 |
|---|---:|---:|---:|
| 補給制限後・旧敵補正・旧罠 | 50 | 0% | 0% |
| 採用候補の探索的比較 | 50 | 8% | 2% |
| 強め候補の独立検証 → 再調整の根拠 | 200 | 7% | 1% |
| 強め候補・極全取得 | 20 | 20% | 10% |
| 同じ20種・強め候補・基準の極 | 20 | 0% | 0% |

極の感度比較は採用前の強め候補による少数試験。永続強化で結果が変わる確認であり、採用設定や全プレイヤーの成功率を示すものではない。

原記録には探索・診断・感度確認を含む13群、計930出撃を収録。繰り返し使用した種を含むので、930件を独立標本として合算しない。最終検証だけは他群と重ならない種200個を使用した。同じ種120001を別ブラウザーで再実行し、全記録が一致することを確認済み。

出荷するゲーム処理のコミットは `23c73051a0c4363e0cf4ced59a950387e68e53e0`。試験時のローカルコミット `76514c9026545b7de4f3807b22238c8c9a6f8c46` とツリーは同一（`2ee7d1611e5070d9846f77e597e0b3fa8d55bebe`）。後続の記録追加ではゲーム処理を変えていない。

検証済み: 全237対象のJS構文、無限迷宮・記録の単体確認、全958技の記録ON/OFF一致、全958技・311出来事952選択肢の一括確認、ブラウザーで補給3個・袋50個・保存復帰・帰還記録、罠の同Lvで5/100/1000階の値が一致し本編の階数補正は残ること。区間比較の原記録は `infinite-stress-results.json.gz` に別保存。

## 再実行

先にリポジトリのルートで `python3 -m http.server 8000` を起動する。PythonのPlaywrightと `/usr/bin/chromium` が必要。

```sh
python3 tools/infinite/fullrun.py --samples 200 --seed 120001 --out /tmp/infinite-validation.json
python3 tools/infinite/fullrun.py --samples 20 --seed 60001 --profile all --out /tmp/infinite-all-boons.json
python3 tools/infinite/fullrun.py --samples 50 --seed 20001 --power 1,1,1,1 --out /tmp/infinite-old.json
python3 tools/infinite/summarize.py /tmp/infinite-validation.json
python3 tools/infinite/summarize.py docs/infinite-fullrun-data.json.gz
node tools/infinite/check.mjs
python3 tools/infinite/browser-check.py
python3 tools/infinite/traps-check.py
```

`--power` は試験ブラウザー内だけの比較用上書き（1・20・50・100階の補正）。省略時は出荷するゲームの式をそのまま使う。上書きは敵の補正だけで、罠の旧式は復元しない。JSONにはコミット・試験ソースのハッシュ・自動プレイヤーのハッシュを記録する。

実プレイでの再調整のため、テスト記録の出撃欄に極の永続強化・直近の能力値・作戦・借用を追加した。既存の5階ごとのHP/MP・道具収支・到達率と合わせて比較する。
