## 分割の基本方針
1. **データとロジックを分ける。** データは「層ごと・職ごとに1ファイル」、ロジックは「機能ごとの縦割り」。`src/jobkit/<job>.js` が成功例。
2. **依存の向きを一方向に固定する** (今の「`ui/` は `game.js` を import しない」の拡張):
   ```
   データ (arts, catalog, jobkit) → 純粋なルール (combat, souls, loot計算)
     → 状態を触るシステム (save, battle, board, town…) → game.js (起動・ループ・結線のみ)
   ```
   下の層から上の層は import しない。
3. **`G` を `src/core/state.js` へ** (`export const G`)。
4. **相互呼び出しの中心 (`endBattle`・`descend`・`returnToTown` など) は最後まで `game.js` に残す。** 先に周辺 (葉) から切り出して、循環 import と読み込み順の問題 (TDZ) を避ける。

## 進め方 (順番が重要)
1. **安全網** — 画面なし (DOM スタブ) での起動確認、Chromium で タイトル→はじめから→出撃→戦闘→帰還 を流す通しテスト、`sw.js` の `ASSETS` が import される全ファイルを含むかの検査 (または ASSETS の自動生成)。`tools/` に置き、`.github/workflows/pages.yml` の公開前に CI で回す (今は無検査で即公開)。
2. **捨てる (挙動ほぼ不変)** — 旧ポップアップ・旧データの読み替え・`x_` 層・旧魔物定義の統合。
3. **尺度の統一 (仕様変更)** — 迷宮Lv 1本、生成器は奈落専用。難易度調整は一度リセットし、テスト記録で測り直す。
4. **データの分割** — `ARTS` を層ごと、`jobart` を職ごと。
5. **`game.js` の分割** — `core/state.js` と `core/save.js` を先に、残りは上の表の順 (葉 → 中心)。
6. **公開直前** — セーブ形式を固め、セーブキーを1つに決めて以後は変換方式のみ。ID の追加専用ルールもここから正式に適用。

### 各段の決まり
- **1 PR = 1つの切り出し**。関数の移動だけで挙動は変えない (改修は別 PR)。
- 関数名は変えない (移動の差分が読みやすく、CLAUDE.md の記述もそのまま通じる)。
- 新しいファイルは `sw.js` の `ASSETS` に足し、`CACHE` を上げる。
- 分割したら CLAUDE.md のモジュール説明も更新する。モジュールごとの詳しい説明は `docs/` に移し、CLAUDE.md は地図と決まり事に絞る。

## 任意 (仕様を変えられるなら検討の価値あり)
