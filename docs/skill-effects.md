# 技の演出

味方の全960技に、実際の作用から割り当てた37系統の共通演出を使う。46技には看板技の余韻と色の調整を重ねる。炎・氷・雷・回復・守り・連撃などを形と音で区別し、弱体・状態異常の印は実際に効いた対象だけに付ける。未命中・無効の対象には命中演出を出さない。通常攻撃は承認済みの5種類を維持し、敵の技・パッシブ・道具は既存の描画を使う。

武器の実物、矢の実物、手・腕・人物は描かない。線、光、波、霧、紋をCanvasで作り、音は既存の効果音と短い共通合成音6種類を使う。火柱のみ、乱流を焼き込んだ18コマの透過アトラス（`art/effects/fire-pillar.webp`、約86KB）を使う。起動時から読み、通常はコマを混ぜて描き、軽量時は本数と描画回数を減らす。取得失敗時も熱の光を表示し、進行は止めない。再生成は `python3 tools/effects/build-fire-texture.py`（numpy/Pillow）。火柱の主音はランク別の噴出・轟音・破裂の合成音にし、火球などの既存音は維持する。動画・音声ファイルと保存項目の追加はない。

火柱は本数の違いだけでなく、3種類の演出に分ける。ランク1は従来の噴炎で8技（最多）、ランク2は中心から左右への連続噴出で獄炎・熔岩流の2技、ランク3は戦闘Canvas全域を回転する二重の炎の渦で、各職業の火系統最上位技（獄炎嵐・灼熱地獄・業火の禁書・浄罪の業火・焔の審判・終焉の焔）の6技だけ。生成元の `fireRanks` に明示し、習得Lvだけでランク3にしない。主音も0.68/0.9/1.15秒と厚みを増す。画面全域の炎は演出であり、技の対象や威力を増やさない。操作ボタンは覆わない。軽量表示でも渦の広がりは保ち、動き低減では回転・粒子を止める。

## 確認する

ゲームの設定「技の演出を試す」または [effects-lab.html](../effects-lab.html) を開く。未習得技の名前も表示するので、設定の入口と確認画面の冒頭に注意を出す。検索・系統の絞り込み・順番の再生・音・軽量表示・動きの低減・全体技の6体表示を切り替えられる。認証情報・本編の保存・進行には触れず、クラウドへの通信もしない。

「全技を検査」は960技×通常/軽量×動き低減ON/OFF×4時点を描く。全技に描画があることと、生成数・対象数の上限を検査し、JSONへ書き出せる。1回の検査結果だけを保持する。

## 制作する

- [全技の割当表](skill-effects-catalog.csv) で、名前・効果・対象と系統の関係を確認する。
- 共通の形は `src/skill-fx.js`、看板技の調整は `src/skill-fx-signatures.js`、生成規則と代表技の個別指定は `tools/effects/build-catalog.mjs` で管理する。
- 分類は制作時に確定する。実行時にMPの多さや技IDのハッシュから形を推測しない。規則を直したら `node tools/effects/build-catalog.mjs` でカタログとCSVを同時に生成する。生成物は手で直さない。
- 実際の習得表の看板技もすべて登録する。既存の演出キーは維持する。大きさ・色・軌跡・余韻で個性を付け、技ごとに別画像を持たせない。
- 全体技は大きな主演出1個と小さな対象の印にする。吸収・攻撃と回復の複合作用は、実際の敵と味方の作用点を分ける。探索の技も同じ部品を短く重ね、入力を止めない。
- ゲーム用乱数・戦闘式・HP/MP更新・通信の確定順序は変えない。火柱以外の演出は220〜350msの既存枠を維持する。火柱はランク1/2/3で400/700/1200ms、オートは60%、手動の高速設定は80%とし、生成した火柱の表示終了まで次の行動を待つ。未命中・無効で火柱を生成しない場合は追加待機なし。軽量表示・動き低減でも尺は維持する。確認画面も同じ尺で最後まで再生する。

## 負荷を抑える

同時エフェクト32、作用点12、補助粒子18（軽量時は各部品で0〜7）を上限とする。全体技で主演出や主音を対象人数分重ねない。連撃の既存の追撃音と数値表示は維持する。Canvasの大きなぼかしフィルターは使わず、必要な主光だけ放射グラデーションで描く。

低性能端末、OSの動きの低減、設定「演出を軽くする」に対応する。自動では描画呼出しが4ms超で6回続いたら軽量化し、2ms未満で240回続いたら復帰する。減らすのは粒子・余韻などで、技の速度と結果は同じ。計測は固定長240件の配列と累積値だけを保持する。

2026-11-02、ヘッドレスChromiumで全組み合わせ15,360描画を確認。CPU通常で平均約0.007〜0.008ms、CPUを4倍遅くした検査で平均約0.030〜0.041ms。一時的な最大値は約22msも記録した。これはCanvas描画命令を発行するCPU時間であり、GPUの描画完了・実機のFPS・実戦全体の性能を保証する値ではない。低性能の実機での見た目と操作感の確認も必要。

カタログ本体は16,293バイト。旧看板技描画の共通化による削減を含め、確認画面込みの変更対象の配信コードは合計で約14KB増加（非圧縮、文書・検査道具は配信対象外）。通信API・セーブ内容は増やさない。

## 検査

HTTPサーバーを8000番で起動して実行する。ブラウザ検査はPlaywrightとChromiumを使用する。

```sh
node tools/effects/build-catalog.mjs --check
node tools/effects/check.mjs
node tools/balance/effect-scope-check.mjs
python3 tools/effects/browser-check.py
python3 tools/effects/game-browser.py
python3 tools/cloud/normal-attack-browser.py
```

全割当・看板技・対象範囲・ゲーム用乱数不変・不発・複合作用・上限・合成音の有限性を検査する。実ゲームでは物理技・単体魔法・全体魔法・回復・自己強化を通し、短い/長い通信で確定前に状態が進まないこと、主演出1個・主音1回・追加通信なしを確認する。従来の通常攻撃とクラウド保存の検査も維持する。ブラウザ検査のJSONと見本は `/tmp/dos-skill-fx-check` に出力し、CIの成果物にも保存する。
