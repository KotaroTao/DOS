# 技の演出

味方の全960技に、実際の作用から割り当てた37系統の共通演出を使う。75技には看板技の余韻と色の調整を重ねる。炎・氷・雷・回復・守り・連撃などを形と音で区別し、弱体・状態異常の印は実際に効いた対象だけに付ける。未命中・無効の対象には命中演出を出さない。通常攻撃は承認済みの5種類を維持し、敵の技・パッシブ・道具は既存の描画を使う。

武器の実物、矢の実物、手・腕・人物は描かない。線、光、波、霧、紋をCanvasで作り、音は既存の共通音とランク別の専用合成音を使う。火柱は、乱流を焼き込んだ18コマの透過アトラス（`art/effects/fire-pillar.webp`、約86KB）を使う。起動時から読み、通常はコマを混ぜて描き、軽量時は本数と描画回数を減らす。取得失敗時も熱の光を表示し、進行は止めない。再生成は `python3 tools/effects/build-fire-texture.py`（numpy/Pillow）。火柱の主音はランク別の噴出・轟音・破裂の合成音にし、火球・爆発にも各ランク専用の合成音を用意する。動画・音声ファイルと保存項目の追加はない。

火柱は本数の違いだけでなく、3種類の演出に分ける。ランク1は従来の噴炎で8技（最多）、ランク2は中心から左右への連続噴出で獄炎・熔岩流の2技、ランク3は戦闘Canvas全域を回転する二重の炎の渦で、各職業の火系統最上位技（獄炎嵐・灼熱地獄・業火の禁書・浄罪の業火・焔の審判・終焉の焔）の6技だけ。生成元の `fireRanks` に明示し、習得Lvだけでランク3にしない。元の主音の噴出・轟きの違いは保ち、再生バッファは共通の表示尺へ合わせる。画面全域の炎は演出であり、技の対象や威力を増やさない。操作ボタンは覆わない。軽量表示でも渦の広がりは保ち、動き低減では回転・粒子を止める。

火球は一発の火球・3発の収束・巨大火球の着弾の3演出で、9/4/3技に配分。爆発は局所の炸裂・時間差の連鎖・戦闘画面全体の大爆発で、6/2/3技に配分する。火球の最上位は炎帝の業火・盗み火・火生三昧、爆発の最上位はLv200の極大消滅・魔闘・天崩・万象崩壊に限定。星砕・魔力暴走・天球崩落などの既存呪文を爆発へ振り分けるが、威力・属性・対象は維持する。素材は `tools/effects/build-thermal-textures.py` で生成する2枚の透過アトラス（合計約157KB）。専用音も各ランクで変え、一手1回だけ鳴らす。

氷・水・風・雷・岩・地にも、単なる拡大ではない3種類の演出と専用音を使う。

ゲームの設定「技の演出を試す」または [effects-lab.html](../effects-lab.html) を開く。未習得技の名前も表示するので、設定の入口と確認画面の冒頭に注意を出す。検索・系統の絞り込み・順番の再生・音・軽量表示・動きの低減・全体技の6体表示を切り替えられる。認証情報・本編の保存・進行には触れず、クラウドへの通信もしない。

「全技を検査」は960技×通常/軽量×動き低減ON/OFF×5時点（尺の5%・30%・65%・92%・終了後105%）を描く。各画質・動き低減条件で途中の描画があり、終了後に消えることと、生成数・対象数の上限を検査し、JSONへ書き出せる。1回の検査結果だけを保持する。

## 制作する

- [全技の割当表](skill-effects-catalog.csv) で、名前・効果・対象と系統の関係を確認する。
- 共通の形は `src/skill-fx.js`、看板技の調整は `src/skill-fx-signatures.js`、生成規則と代表技の個別指定は `tools/effects/build-catalog.mjs` で管理する。
- 分類は制作時に確定する。実行時にMPの多さや技IDのハッシュから形を推測しない。規則を直したら `node tools/effects/build-catalog.mjs` でカタログとCSVを同時に生成する。生成物は手で直さない。
- 実際の習得表の看板技もすべて登録する。既存の演出キーは維持する。大きさ・色・軌跡・余韻で個性を付け、技ごとに別画像を持たせない。
- 全体技は大きな主演出1個と小さな対象の印にする。吸収・攻撃と回復の複合作用は、実際の敵と味方の作用点を分ける。探索の技も同じ部品を短く重ね、入力を止めない。
- 全37系統はランク1/2/3以上で400/700/1200msに統一する。ランク4・5以上でも1200msを超えない。オートは60%、手動の高速設定は80%（両方ならオート優先）。画質・動き低減で尺を変えず、生成した主演出の終了まで次の行動を待つ。全て未命中・無効で生成しない場合は追加の演出待ちを付けない。探索は同じ尺で表示し、入力を止めない。
- 連撃は定義上の `hits` / `scatter` の回数をランクにする（2連撃はランク2、5連撃はランク5）。対象人数・成功回数では格を変えない。全体2連撃は対象6体でもランク2。打数の時間枠を共通尺へ収め、外れた枠には命中光を出さない。数値と追撃音も同じ枠へ合わせる。
- 系統本来の形と音色を保ち、上位は二重の波・外周の紋・収束する光、合成音の低音・倍音・時間差の層を重ねる。音は表示と同じ長さのバッファを一手1回再生し、オート・高速では再生速度を合わせる。ランク3以上の音と追加光は3相当を上限にする。追加の音声・画像ファイルは不要。
- 動き低減は全系統で固定時点の形を表示する。移動・回転・連続する打撃光を止め、打数は結果の数値表示で伝える。
- 弱体は `_applyMod` が実際に適用した結果だけを `hit.debuff` / `mods` に記録する。HP/MP吸収は実際の受取側へ印を置く。MP吸収の成功量は `mpHeal` に記録し、戻りの光とMPの印は青にする。ゲーム用乱数・戦闘式・HP/MP更新・通信の確定順序は変えない。

## 負荷を抑える

同時エフェクト32、作用点12、補助粒子18（軽量時は各部品で0〜7）を上限とする。全体技で主演出や主音を対象人数分重ねない。連撃の既存の追撃音と数値表示は維持する。Canvasの大きなぼかしフィルターは使わず、必要な主光だけ放射グラデーションで描く。

低性能端末、OSの動きの低減、設定「演出を軽くする」に対応する。自動では描画呼出しが4ms超で6回続いたら軽量化し、2ms未満で240回続いたら復帰する。減らすのは粒子・余韻などで、技の速度と結果は同じ。計測は固定長240件の配列と累積値だけを保持する。

旧検査（2026-11-02）では、ヘッドレスChromiumで全組み合わせ15,360描画を確認。CPU通常で平均約0.007〜0.008ms、CPUを4倍遅くした検査で平均約0.030〜0.041ms。一時的な最大値は約22msも記録した。これはCanvas描画命令を発行するCPU時間であり、GPUの描画完了・実機のFPS・実戦全体の性能を保証する値ではない。低性能の実機での見た目と操作感の確認も必要。

初期導入時のカタログ本体は16,293バイト。旧看板技描画の共通化による削減を含め、確認画面込みの変更対象の配信コードは合計で約14KB増加（非圧縮、文書・検査道具は配信対象外）。通信API・セーブ内容は増やさない。

## 連撃と職業の最終奥義（2026-11-03）

連撃は結果の各命中を順に描く。二連は二回、六連は六回、ランダム連撃は実際に命中した相手へ一回ずつ斬撃（連射は射線）を出す。未命中・無効・吸収に伴う回復は打数へ含めない。軽量・動き低減でも打数を減らさない。1打160ms（最低400ms）、オート60%・高速80%で表示終了まで次の行動を待つ。対象ごとの主演出の複製は行わない。
