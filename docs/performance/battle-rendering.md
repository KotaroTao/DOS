# マージ後の戦闘性能の追加調査（2026-11-06）

対象: PR #1484のマージ `0b444e75bf966e77fae8e79f851242a6d120430d`。PR #1484はmainへマージし、Pages公開の成功と公開サイトのsw.jsの版の一致も確認済み。

## CPUプロファイルで確認した残りの負荷

Chromium・390×844・CPU 4倍低速化で40秒の連続オートを記録した。JSのサンプルで、戦場の `getBoundingClientRect` に約1.4秒、街のアニメーションループ `_tick` からの `getClientRects` に約1.1秒が現れた。これらは呼び出し内部のスタイル計算も含み、純粋なJS計算量ではない。サンプリングによる値で、厳密な累計時間ではない。

### 同じ属性を書き直さない

戦場の前後列ボタンは、毎描画で `hidden` と `disabled` を設定していた。直後に戦場や名前帯の寸法を読むため、同じ値でも属性変更に伴うスタイル再計算が入りうる。現在値を比較し、変わる時だけ書く。

4体の敵を出し、CPU 4倍低速化で100回の描画を3組実施した比較:

| 対象 | 変更前 | 変更後 |
|---|---:|---:|
| スマホ幅390px・不要なボタン属性更新（300描画） | 300回 | 0回 |
| タブレット幅1024px・不要なボタン属性更新（300描画） | 600回 | 0回 |
| タブレット幅・スタイル再計算 | 300回 | 24回 |
| タブレット幅・100描画の時間の中央値 | 118.6ms | 74.8ms |
| スマホ幅・100描画の時間の中央値 | 95.0ms | 97.1ms |

この検査ではスマホ幅の所要時間に改善を確認できなかった。タブレット幅では非表示の前後列ボタンへ毎回hiddenを書いていた差が大きい。数字は一組の比較で、全端末の改善率ではない。

### 非表示の街の寸法を読まない

街のCanvasは画面遷移後もDOMに接続されたまま残る。`townart.js` の共有アニメーションループは、非表示の街でも毎秒何度も `getClientRects` で表示状態を確かめていた。

`[hidden]` / `.hidden` の祖先を先に調べ、隠れていれば寸法取得を省く。反復描画の検査で、非表示Canvasの寸法取得は34〜37回から0回になった。街の表示中の描画頻度は変更しない。

### 街の残りコマの生成を戦闘へ割り込ませない

街の絵は初回の1コマを表示した後、残りを `requestIdleCallback` で生成する。ただし500msの期限があるため、戦闘中にも重い画素計算を始めうる。街のアニメーションが非表示でもこの生成キューは動いていた。

戦闘表示中と背面タブではキューの処理を保留し、復帰後に続きから実行する。既存のコマ・キューは捨てず、待機中の確認は200msのタイマーで行う。戦闘中の保留と街へ戻った後の再開をブラウザで検査する。

同じ隊・敵・乱数の設定、390×844、CPU 4倍低速化で変更前と変更後を各40秒計測した。CPUプロファイルを採らない回同士で比較した。

| 対象 | 変更前 | 変更後 |
|---|---:|---:|
| フレーム間隔p95 | 33.3ms | 33.3ms |
| 最大フレーム間隔 | 333.3ms | 333.3ms |
| Long Task件数 | 20 | 14 |
| Long Task合計 | 1733ms | 1154ms |
| 戦場描画時間の合計 | 5986.5ms | 6422.2ms |

両方とも作戦Workerは12回成功、同期版への退避0回。長い処理の合計は減ったが、フレーム間隔とスマホの戦場描画全体は改善を確認できなかった。サンプル数1の比較であり、約33%のLong Task合計削減を全端末の性能向上率とは扱わない。別のプロファイル採取回では長いフレームも残り、引っ掛かりの解消は保証できない。

## 変更しなかったものと限界

- 技の結果を決める式、乱数、オート作戦の判断は今回の変更対象外。
- 一撃400msなどの演出時間と追加行動間隔は既定仕様を維持。演出を短くすれば総時間は減るが、計算の最適化とは別の仕様変更になる。
- 戦場の寸法取得は画面回転・名前帯・前後列切替に追従する必要がある。単純な永久キャッシュでは位置が古くなるため、今回導入しない。
- 静止背景の追加Canvasキャッシュも検討したが、プロファイルではまずDOMの寸法問い合わせが目立った。追加の保持メモリを使う背景キャッシュは、今回の計測だけでは採用を正当化できない。
- CPUプロファイルの大きな `(program)` 区間はJS関数に帰属できず、描画・ブラウザ側の処理を含む。すべてを戦闘計算のせいと断定しない。
- 公開サーバーの応答時間と実機Safariは未計測。前回同様、通信やGPU処理も含めて引っ掛かりがすべて消えるとは言えない。
