# オートの見積もり計算の短縮（2026-11-06）

PR #1486をmainへマージした `8409038f` を基準に追加実装した。マージ前にCIで見つかった欠落画像の待機経路も修正し、画像を一部省いた状態で非表示Canvasの寸法取得が0回になることを再検証した。

## 変更内容

`autotactics.js` の通常攻撃・物理技・攻撃呪文の予測は、敵の既知情報による値と、無効・低威力確認用の実値を常に両方計算していた。3ターン予測の各候補でも繰り返すため、技・敵・支援候補の多い隊ほど回数が増える。

実値の確認を先に行い、次の場合は既知情報による再計算を省く。

- 無効・低威力だった場合。従来から最終的に実値を採用している。
- 属性と抵抗値がどちらも既知の場合。慧眼の適用も含めて、2つの計算の前提が同じになる。

属性の開示条件はcombat.jsの既存の判定を `estimateElementKnown` として共有する。属性だけ既知・抵抗値だけ既知などの場合は共用せず、従来どおり別計算する。未知の弱点・部分耐性を作戦に混ぜない。状態異常の成功率も、抵抗値が既知なら同じ値を再計算しない。

値や計算式を近似する変更、候補を間引く変更、戦闘をまたぐキャッシュは導入しない。戦闘結果・乱数・演出時間・セーブ形式は維持する。

## 検証結果

5作戦×属性開示2条件×抵抗値開示2条件×7場面（通常・深手/蘇生/MP不足・無効・金属・技の制限・慧眼/双魂・魔法武器/属性吸収）=140条件で、従来の二重計算を行う比較用モジュールと照合した。

- 全候補の値打ち・支援予測・最終採点と、選んだ行動/技/対象が完全一致。
- 入力の戦闘状態と乱数状態は不変。
- 両方既知の条件のestPhys/estSpell/estRate呼び出し合計は164,404回→82,202回（半減）。
- 同一の重い条件をウォームアップ後に交互に6回ずつ測ったNodeの中央値は42.9ms→31.2ms（約27%短縮）。別の簡易比較でも15条件の候補が一致し、計算合計が約1.87秒→1.18秒だった。

これは作戦計算部分の測定であり、戦闘全体が27%速くなるという意味ではない。実際のゲームではWorkerで計算し、通信・画像・描画・既定の演出時間も含まれる。未開示の敵では計算を共用できない場合もある。実機Safariと公開サーバーの応答時間は未測定。

全960技と全356出来事・1,026選択肢、37職×Lv40/120の74条件・1,480模擬戦も実行した。Workerの同期版との一致は30条件で確認し、既知の敵との40秒連続オートも変更前後ともWorker13回成功・同期版への退避0回だった。実戦のフレーム間隔p95は両方16.7msで、この比較で画面全体の滑らかさの改善は確認できなかった。

## 採用しなかった案

静止背景を一度Canvasに焼いて転写する案も、背景・寸法・倍率を変えて実測した。画素は一致したが、200描画で既存3〜10msに対し転写6〜34msと遅かったため、実装しない。3ターン予測の技一覧・射程候補の共通化も試作したが、時間短縮が安定せず採用しない。
