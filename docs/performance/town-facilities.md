# 街の施設の表示待ちを短くする（2026-11-06）

PR #1496（`ce3999ae`）はmainへのマージ・Pages公開・公開サイトの版の一致を確認済み。後続のmain更新 #1497も取り込み、以下の比較基準は `095c1c07`。

## 調査と実装

街・館・商会・王宮・酒場・祠・宿屋を実際に巡回した。CPUプロファイルでは画像待機の位置確認、旧ドット絵の生成、進行の正規化、依頼の迷宮探索が目立った。

1. 焼き付け済みの施設の背景は既存の `_base` からすぐに描く。共通の画像取得キャッシュから原画が解放された後も、焼いた背景を使い、再取得・再復号・解決済みPromiseによる場面待ちを作らない。
2. 番人・王・紋章は、既に読み込んだ画像を同期描画する。初回の取得待ち・失敗時の通知は維持する。画像は元から保持しているPromiseの解決値と同じものを使い、新しい原寸画像やビットマップの保管枠は増やさない。
3. 待機完了済みの画像の表示位置は調べずに片付ける。場面の準備確認も、未完了の要素だけ位置を確認する。画面外の画像は引き続き待たない。
4. 原画が登録されている街・施設の旧ドット絵は裏でも生成しない。原画が未登録の場合の下ごしらえは維持する。登録された原画の通信失敗で旧絵へ戻る変更ではない。
5. 固定依頼の討伐対象から得られる迷宮候補だけを定義ごとのWeakMapに保持する。解放された迷宮の選択は毎回行う。地図の一括参照では、同じ進行表を迷宮数ぶん正規化し直さない。解放・報告・依頼の受注/達成・セーブの状態はキャッシュしない。

背景・人物・文・ボタン・解放条件・所持金・保存形式・乱数は変更しない。初回画像が遅い時や失敗した時は、従来どおり直前の画面を保持し、準備中の中身への二重操作を防ぐ。

## 検査

- 施設の絵・番人・王・紋章を32回比較し、再表示時の画素が一致、その場で描画できて不要な場面待ちが0回であることを確認。
- 共通の画像取得キャッシュを追い出した後も、焼き付け済みの施設の背景を再取得せず、同じ画素で即表示。
- 初回の取得を止めて、直前の画面保持と入力保護を確認。通信失敗時も旧画面と再試行を保ち、通常の画像待機で全画面を覆わない。
- 原画がある場合の旧絵準備0回、未登録の場合の下ごしらえを確認。
- 固定依頼86件について、地図の交換・同じ解放表の直接変更を含む860条件で変更前と対象迷宮が一致。準備後の候補探索は魔物一覧の生成1,602→0回。一括解放数の参照は進行表を1回だけ読む。
- 既存の画像遅延/失敗・街の往復・待機・旧絵非表示・依頼の対象/解放・街の装備通知・戦闘開始・迷宮入場・タイトル受け渡しと全JS構文の検査を通過。

燭台の既存検査は、制作ロゴが画像準備完了まで燭台を隠すため迷宮/起動待ちで停止していた。この検査の当該2場面だけロゴを分離し、画像待機と燭台の動作を確認するようにした。製品のロゴ表示・時間・処理は変更しない。
