## 原画と配信画像

各迷宮につき画像生成で1536×1024の原画を2枚制作した。

- `w0N-materials-master.png`: 上段の蓋3種と右下の壁材。下段左の床は制作見本として残し、ゲームには使わない。坑口だけ上段の実際の境界が496pxなので、切り出し高さも合わせる。
- `w0N-floor-master.png`: 盤面用の連続した一枚の床。鏡合わせや反復を使わず、盤面の縦横比で切り出す。
- `art/dungeon/w0N-materials.webp`・`w0N-floor.webp`: 品質88で変換した配信用画像。10枚で約5.8MiB。原画・比較画像は公開配置に含めない。

地下墓地の石材と床を画風の参照に使用。回廊は灰と石灰岩、修道院は黄土色のモザイク、取水口は冷たい湿った石、坑口は鉱石とさび、外郭は風化した敷石で区別する。

人物・小物・魂火にはmainに導入済みの共通素材を使用する。魔物と物語の挿絵は今回の対象外。

## 描画

`src/cryptpaint.js` は訪れた迷宮の二枚だけを遅延取得する。迷宮ごとに読込状態を分け、二枚が正常な寸法で揃うまで旧描画を使う。一方の失敗・不正寸法で別の迷宮の素材は止まらない。素材到着時はキャッシュを切り替える。盤面キャッシュは従来通り2組まで。

床・蓋は論理寸法の3倍で保持し、壁の上面と側面、光と影、めくりを重ねる。蓋の彫刻は中身に依存せず、描画で遊びの乱数を使わない。汚水・坑内ガス・鉄菱の染みは既存の色と模様を新しい床に重ねる。落ちる床と動く粒は既存の描画を継続する。

## 再変換と確認

```bash
bash tools/crypt/build-dungeons.sh
python3 -m http.server 8000
# 別の端末。Playwrightのあるnode_modulesをNODE_PATHに指定する。
NODE_PATH=/path/to/node_modules CHROMIUM_PATH=/usr/bin/chromium node tools/crypt/verify-dungeons.cjs
```

確認対象: 対象60階と地下墓地5階、幅320/390/600/1280px、取得失敗・片方の失敗・寸法不正・遅延、タップとめくり・ドラッグ・全体表示、蓋と中身の独立、遊びの乱数、危険な床、対象外の迷宮、キャッシュ上限。ローカルChromiumで検証し、スマホ実機の速度測定は含まない。
