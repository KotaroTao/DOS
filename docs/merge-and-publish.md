# マージから公開確認まで

ユーザーがPRのマージを指示した後は、検査・マージ・Pages公開・公開サイトの版確認を一度の実行にまとめる。

```bash
python3 tools/release/merge.py <PR番号> --head <確認済みの40桁コミットSHA> --merge
```

`gh` が使える環境で実行する。ネットワーク許可が必要な環境では、このコマンド全体に通信の許可を付ける。確認と待機のたびに別の通信コマンドを出さず、同じ実行の出力を受け取る。環境の承認規則を変更する道具ではないため、承認ボタンの回数は環境によって異なる。

- `--merge` を省くと、未マージのPRでは読み取りだけで止まる。
- 承認したコミットとPRの最新コミットが異なる場合、main以外を対象にする場合、下書き・衝突・検査失敗の場合はマージしない。
- 検査待ちと公開待ちは10秒間隔、既定15分まで。GitHubの保護規則を回避するオプションは使わない。
- マージ後は、そのマージコミットの `pages.yml` の成功と、公開サイトのsw.jsの版の一致まで確かめる。別の更新が先に公開されていたら、コミットの履歴を比較し、このマージを含む後続版であることを確認する。「マージ済み」と「公開済み」を別に報告する。
- 中断・時間切れの後は同じコマンドで再開できる。既にマージ済みなら、もう一度マージせず公開だけを確認する。

公開処理は原画・制作記録（docs/、art/story-review/）とtools/を最初から取得しない。出荷物の一覧・サイズ・キャッシュ版の検査は引き続き実行する。GitHubの待ち行列や公開配置にかかる時間は、この道具では省けない。

道具の停止条件を確かめる:

```bash
python3 -m unittest discover -s tools/release -p 'test_*.py'
```
