# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-page, build-free browser RPG (ウィザードリィ風／魂の迷宮 - Dungeon of Souls). Pure HTML + ES Modules + Canvas — **no bundler, no package.json, no npm, no test runner, no lint config.** All monster/hero/item art is drawn programmatically as pixel art on Canvas. The only image assets are user-provided illustrations under `art/`, normally converted to true pixel art (one dot = one pixel, palette-reduced) — currently `art/op_dolls.png`, the opening's 人業 scene. Exception (by user request): `art/mansion_irene.jpg`, the 人業の館 mistress イレーヌ, is the user's painted illustration used as-is (1172×420 JPEG, no pixel conversion; drawn smoothly, not `pixelated`) under the 隊 tab and in her greeting scene — `keeperPanel` in `src/ui/party.js`, fills only the height left over and folds away via container queries in `ui-party.css`); list each in `sw.js` ASSETS. Ships as a PWA (manifest + Service Worker, offline-capable).

The game has a town hub, a **map of hand-built dungeons you choose between** (`src/dungeons/world.js` — 17 so far (chapters 1-3 + 4 side dungeons), growing past 100; each unlocks by a condition), a master-search story (`src/story.js` + illustrations `src/storyart.js`), a souls system, codices, quests, and an element/affinity system. When README and code disagree, trust the code.

## Running & "building"

There is no build step. Because it uses ES Modules, you must serve over HTTP (not `file://`):

```bash
python3 -m http.server 8000   # then open http://localhost:8000/
# or: npx serve .
```

Deploy is automatic: pushing to `main` triggers `.github/workflows/pages.yml`, which uploads the repo root as-is to GitHub Pages (https://kotarotao.github.io/DOS/). No build/test job runs in CI.

### Verifying changes without a browser
There is no test suite. To sanity-check JS edits, use Node:
- Syntax: `for f in $(git ls-files 'src/*.js'); do node --check "$f"; done`
- Module load / logic: a DOM-stub harness (`globalThis.document/window/localStorage/AudioContext` fakes) can `import('./src/game.js')` headlessly to catch load-time errors, and pure logic modules (`combat.js`, `dungeons/*`) can be imported and exercised directly. When testing combat in isolation, first `Object.assign(MONSTERS, DUNGEON_MONSTERS)` because that merge normally happens in `game.js`.

### Service Worker cache — bump on every shipped change
`sw.js` caches assets under a versioned key (`const CACHE = "dos-vNN"`). **Whenever you change any shipped file (JS/CSS/HTML), bump this version** (e.g. `dos-v53` → `dos-v54`), or returning players keep the stale cached copy.

## Architecture

### Module layout (`src/`)
- **`game.js`** — the hub. Owns the single global game state `G`, the main loop, input, all screen rendering (town/board/battle/status/codex overlays), and the bridge between board exploration and turn-based combat. By far the largest file; most features touch it.
- **`board.js`** — maze generation. Edge-walls (walls live on the *boundary* between cells, not as cells), dead-end event placement, stair placement, return portals — **world dungeons (`cfg.gates`)**: on every 5th floor except the bottom (5/10/15…) the down stairs itself *is* the portal (`cell.gate = true` on the `stairs` cell, so 道しるべ/warp-to-stairs keep working; drawn as a portal via `isPortalCell` in game.js); stepping on it (or the dock's 降りる) opens `askGate`: 先へ進む / 街へ帰還する / まだ探索する, and records `G.world.gates[id]` = deepest gate reached — the departure sheet then offers 「潜り始める階」 B1F / B5F 陣 … (`startFloorsOf` → `departNow({from})` → `enterDungeon(mut, startFloor)` → `arriveAtGate` puts the party on the gate). No other floor has a portal; reaching the bottom (clear) or killing the boss also lets you go home. The abyss (no `gates`) keeps the old `type:"portal"` rule (every 5th floor + 20% elsewhere), poison-floor tiles (`type:"poison"`, corridor cells, `cfg.poisonRate` from the dungeon generator — rank 3 band and deeper) and **pitfalls** (`type:"pit"`, corridor cells, `cfg.pitRate` from layer 2 (D6+), never on the bottom floor nor in the abyss): stepping on one drops the party to the next floor (`descend({fall:true})` in game.js, no damage; walking aborts via `G._walkAbort`, `findPath` routes around revealed pits). **浮遊** (`G.run.float` = floors left incl. the current one, decremented in `descend`) cancels both pits and poison-floor damage; it is cast from the dungeon dock with a `kind:"field"` skill (`FUYUU`: thief 7 / arcthief 12 / monk 12) — field skills never appear in battle (`battleSkills` filters them). **探りの術** (`kind:"field"` + `sense`, job-unique skills in that job's jobkit file, this floor only — `G.board.fsense[enemy|chest|stairs]`, reset by `newFloor`): 狩人 Lv22 気配読み `HUNTER_KEHAIYOMI` (unrevealed monster cells glow a soft red — no type/elite info), 盗賊 Lv50 宝探し `THIEF_TAKARASAGASHI` (chests glow a soft blue, mimics indistinguishable) — both drawn by `drawSenseGlows` (also while walking) — and 司教 Lv22 道しるべ `BISHOP_MICHISHIRUBE` (stairs 「▼」 + outline in `drawBoardHighlights`, and flips the 8 cells around the stairs face-up via `revealAroundStairs` — not cleared, so stepping on them still triggers them; the stairs card itself stays face-down because a revealed stairs can be descended from anywhere; refused once the stairs are revealed); they replaced 烈風斬/冥刃/アクアウェイブ in those slots. Dock: every field skill someone in the party knows gets its own button (`spec.fields` → `dockField(key)` → `castField(key)`, caster = `fieldCaster(key)`; no grouped chooser) — lit while active (浮遊/道しるべ teal, 気配読み red, 宝探し blue). Crowding in `renderDock`: 2+ field skills → they become 札 (icon + short name); a field skill and ≥4 buttons (or ≥5) → `.tight`, 帰還/回復 also become 札; ≥7 buttons → 降りる too (`DOWN_SHORT`).
- **`traps.js`** — pure trap/chest-rank data: `TRAPS` (24 trap defs, trap rank 1-3 — rank gates appearance by dungeon rank, so all 24 appear from dungeon 21+), `pickTrap(dungeonRank)` (weights dangerous traps heavier in deeper dungeons), and chest ranks 1-5 (`CHEST_RANKS`/`rollChestRank` — deeper floors/dungeons roll higher). Execution/animation lives in `game.js` (`springTrap` applies effects for floor traps and chest traps alike; `disarmNeed(chestRank)` makes disarm difficulty a function of dungeon rank × chest rank; higher chest rank also boosts loot in `chestContents`).
- **`levelcurve.js`** — **レベルデザインの1か所** (2026-10、ユーザーの指示「6人を均等に育てて 7時間で Lv50・20時間で Lv100・以降20時間ごとに +100」)。1Lv の目標分数 `lvMinutes(L)` (Lv1-49: 4.25分 + 0.18分ずつ = 計7時間 / Lv50-99: 15.6分 / Lv100-: 12分)、敵Lv L の普通の1戦の ✦Soul `refSoul(L)` (Lv100 まで 10 + 0.4L²、以降 +80/Lv) と金貨 `refGold(L)` (= ✦ の 0.7倍)、魂の強化費用 `trainCost(L)` = refSoul(L) × lvMinutes(L) × `EXP_PER_MIN` (= 1時間57戦 × 死体などの上乗せ1.3 × 魂1つへの配分0.5 ÷ 60) — Lv に合った迷宮で戦えば狙いの分数で1Lv上がる。`lvPow(L)` (= souls.js の lvlFactor) は敵の強さの Lv 補正、`emberMul(L)` = ceil(L/50) は残火の数。推奨Lvの割り付けは本筋の迷宮を1階 `MIN_PER_FLOOR` 3.1分で順に潜った時刻の `levelAtMinutes`。テスト記録 (`fl`/`ms`/`sl`/`soul`) が届いたら BATTLES_PER_HOUR / EXTRA / MIN_PER_FLOOR を実測で合わせる。
- **`telemetry.js`** + **`baseline.js`** — 戦闘バランス調整の材料集め (挙動には影響しない)。`telemetry.js` = テスト記録: 設定「自動化・データ」→「テスト記録」で ON にすると、迷宮ごと (迷宮の id `w05` / 奈落は `A3`。旧来の `D10` の欄も残る) に隊の様子 (1階到着 `f1`・最後の階 `last`・踏破 `clear` 時の各人業の職/Lv/能力値) と戦闘の集計 (種類 n=通常/e=精鋭・ミミック・出来事/b=主 ごとに 勝/逃/全滅・ラウンド・先制/奇襲 (奇襲の出どころ `ambR` 抽選 / `ambX` 出来事・待ち伏せ と、抽選の奇襲率の合計 `ambP` = 予想回数)・物理の試行/回避/見切り (味方→敵 `pa/pe/pp`・敵→味方 `ea/ee/ep`)・手番で味方が先だった組 `of/op`・逃走 `ft/fo/fs`・与/被ダメ・戦闘前後の隊HP割合・隊平均/敵最大AGI) 、さらに戦利品 (迷宮で得た品のレア度別の数 `loot` = c/uc/r/sr/lr/misc/use・図鑑の新種 `nw`・置き去り `lost`、得たゴールド/✦Soul `gold`/`soul`)、職業の魂のレア度別の数 (`sl` = 迷宮の中 / `tsl` = その迷宮へ入る前の町 — 依頼・宝物庫の褒賞など、c/r/e/l。`grantSoulQuiet`/`grantRewardSouls` → `tlSoulGot` → `tlSoul`、町の分は `S.townSl` に溜めて1階到着で持ち込む)、着いた階の数 `fl` (1階ごとの `tlSnapshot`) と実プレイ時間 (迷宮の中 `ms` / その迷宮へ入る前の町 `tms`。game.js の5秒ごとの時計 → `tlPlayTick`、町の分は1階到着の `tlSnapshot` で持ち込む) を `localStorage['dos-testlog']` (セーブとは別、はじめからでも消えない) に溜め、「書き出す」で要約+JSON をクリップボードへコピーする。game.js のフックは `startBattle` (`tlBattleBegin` → `G.battle.tl`)・`animateResult` (`tlHits`)・`endBattle` (`tlBattleEnd`)・`newFloor`/`commitDungeonClear` (`tlSnapshot`)・`runGainItem`/`runLost`/`runGainGold`/`runGainSoulPts` (`tlLoot`/`tlLost`/`tlGain`)、命中・手番・逃走の数は combat.js の `Battle.tally` (`_physical`/`_startRound`/逃走) が数える (乱数は消費しない)。`baseline.js` = **基準の隊** `PARTY_BASELINE` (「レベル上げをほぼせず普通に進めた隊」の迷宮ごとの平均能力値。テスト記録の実測で1層ずつ行を足す) と `baselineAgi(progressX(n, floor, floors))` (進行度 x = 迷宮番号−1 + (階−1)÷全階数 — 最下階でも1未満なので、踏破時と次の迷宮の入口 (町で育てた後) が別の点になる。実測点を直線で結び、前は (x=0, 7) から、先は +2.4/迷宮で延ばす。実測: 第1〜3層 D1-D14 の f1/clear + D15 の f1、同じ周回の29点。第3層の行は下記 2026-10 の改定前の隊なので、改定後のテスト記録で第1〜3層とも測り直す)。逃走判定と敵の物理の回避 (下記) が `fleeScale` 経由で使う。
- **`events.js`** — 迷宮のイベント (出来事マス `type:"event"`, `cell.evId`). **85 events: 33 common (`c01`-`c33`, any layer) + 10 per layer for layers 1-4 (`l1_*`…`l4_*`) + 12 for layer 5 (`l5_*`, the forest side dungeon and chapter 3)**, choice-based with a free 「立ち去る」 (the cell stays; you can come back) — **except 極 (mythic)**, which have no choices: `gift(A, cell)` grants a permanent boon the moment the cell is stepped on (`once: true` per save, `boon` text for the codex; effects in `EV_BOONS` → `G.events.flags` `will`/`blackCat`/`sewerMap`/`temper`/`salute` (先手 +8%)/`mistEye` (奇襲 ×0.5), read by game.js `evBoon` in `runGainSoulPts`/`evBattleStart`/`startBattle`; `loadGame` grants them to saves that met the old choice-based versions). **Never offer a choice that does nothing** (it would duplicate 立ち去る) — hide choices with no effect right now (e.g. heals when nobody is hurt). Revival events: c31 生命の雫 (common, `cond` = someone dead, one member at HP1), c32 闇医者 (uncommon, inn cost ×3 heal / mansion repair cost ×3 revive, `A.revive`/`A.deadList`), c33 神聖なる泉 (rare, deep, revives all + full HP/MP). Tiers `EV_TIERS` (常 common / 稀 uncommon / 秘 rare = once per run / 極 mythic = once per save) — `pickEvent` first draws the tier by `share` (62/28/8/2, renormalized over the tiers eligible here), then an event in it (that layer's own events ×3, `LAYER_W`). Gating fields: `layer`, `minFloor`, `deep` (back half of the dungeon), `minLv` (this floor's 推奨Lv), `maxSkip` (floors needed below), `cond(A)`; the first dungeon (w01) only rolls common. Placement: `evNewFloor` in game.js (called from `newFloor`) puts at most one event per floor (`EV_FLOOR_RATE` 0.55, D1 0.25) on a dead end; not in the abyss. Rewards are sized in **「戦果」 units = one ordinary battle's gold/✦Soul for this dungeon/floor** (`evUnit`) and go through the existing pipelines (`pickLoot` with `noLR`, `acquireSoul`, chests via `chestHere` → `askOpenChest`), so `lootCapR` still holds; events never give LR or Red Soul. **events.js never imports game.js** — every board/battle/reward operation goes through the `evApi` object (`A`) built in game.js. Fights use `A.fight(cell, specs, tag, {noChest, opening})`; specs are resolved to concrete keys and stored in `cell.evFight` (serializable), `endBattle` marks `won` and, after the results sheet, calls `eventFightWon` → the event's `onWin` (multi-stage fights chain from there; fleeing leaves `evFight` so revisiting offers a rematch). State: `G.events` (saved: `seen`/`picks`/`once`/`flags`/`fresh` — the 見聞録 codex segment in `ui/palace.js`, plus permanent flags `sewerMap`, `bossWeak[layer]` (l1_09 / l4_09 / l5_12), `lore`), `G.run.ev` (this run: `mods` like `{enemyMul}`, preempt/ambushNext/startHeal/bomb/crit/edef/saves/ruby/noBeast/mapChest/bounty…), `G.board.ev` (this floor: `mods` with `dmgMul`/`prey`, oath/miner quests checked by `evProgress`). Run/floor `mods` are merged into `activeModifierDefs` (so `enemyMul`/`chestRankUp` work like mutators); combat buffs are copied to party actors at battle start (`evBattleStart`: `_evDmg`/`_evPrey`/`_evCrit`/`_evEDef`/`_evSave`, read by combat.js `evDealMul`/`edefOf`/`_die`). 鍛え直し sets `item.forge` and `applyForge` (items.js) — re-applied after `reflattenItemStats`; `itemName` appends ＋N. Board icon `ICONS.event` (violet rune stone). **Event-only monsters** (`EVENT_MONSTER_DEFS` in bestiary.js, flag `evOnly` → excluded from `RANK_POOLS`/dungeon rosters, listed in the codex 「その他」 tab via `CODEX_OTHER`): a fight spec `{ key, ranked: n }` spawns them through combat.js `spawnRanked` at **(this floor's top regular rank, `mimicRef().rank`) + n** on the `rankStats` curve (solo HP ×2.2), so they stay one rank above the floor in every layer — e.g. c19 「檻の中の人業」's 檻番の獄卒 `bs_cagewarden` (`ranked: 1`). Their HD art lives in `tools/hdart/event/` (`node tools/hdart/run.mjs event --apply` writes the 「出来事の魔物」 hd_* block after layer 2's). `floorFacts` in dungeonhud shows active event effects (`game.eventFacts`). **Adding an event**: append to `EVENTS` (ids are saved — never rename/reuse), keep the risk↔reward ladder (common ≈ 戦果1-2, uncommon 3-5, rare 8-12, mythic = permanent/lore), always end a choice with `A.done(cell)`/`A.back()`/a next screen, and run the headless sweep (every event × every choice) before shipping.
- **`quests.js`** — 酒場「沈まぬ灯」の依頼 (クエスト). The old 納品依頼 (`G.deliveryQuests`), the dead `QUEST_DEFS`/`dailyQuests`/`subQuests` (subquests.js removed) are all folded into it. Two kinds: **フリークエスト** (掲示板) = `rollBoard(ctx)` posts `BOARD_SIZE` (4) offers — 1 納品 + kill (a monster from an open dungeon, note = where it first appears) / soul / chest / floor (reach B{f}F of a given dungeon; arriving via a gate counts) — kill/floor pick their dungeon from `questDungeons()` (game.js: open dungeons in the order they appeared on the map = key order of `G.world.open`, minus those whose 推奨Lv exceeds the party Lv by `QUEST_LV_GAP` 8 = 出撃シートの「無謀」) weighted ×2 per step newer (`pickDungeon`), so the newest dungeon gets about half; soul/chest rewards scale on the deepest of that list — re-posted on **every return to town** (`returnToTown` → `rollQuestBoard`) — except an idle run (`idleRun`: never left the start floor, no kills/loot — e.g. entering by a gate and leaving at once); the 帰還の鈴 (`RECALL_ITEM`) comes about **once per hour of real play**: when `bellDue()` (game.js: `G.stats.playMs` − `G.quest.bellAt` ≥ `BELL_EVERY_MS` 1h and no accepted bell quest outstanding — `hasBell`), `rollBoard` adds `reward.items = [[RECALL_ITEM, 1]]` to one non-deliver offer (re-offered on every repost until accepted); claiming it sets `bellAt` (`grantRewardItems` puts it in the first bag with room; the claim is refused while no bag has room); offers must be **accepted**, at most `FREE_CAP` (5) at once; accepted ones persist across returns until reported (報告) or abandoned (放棄 → frees the slot). Rewards are sized in 戦果 units (`questUnit(cfg, floor)` in game.js = one ordinary battle's gold/✦Soul there) and may include job souls; 納品 rewards **one** job soul whose rarity is drawn by the item's rarity (`DELIVERY_REWARDS`; the odds are never shown — the reward reads 「職業の魂 (ランダム)」) and can buy the item from the shop shelf on the spot. A 納品 offer can be delivered straight from the board without accepting it (`deliverQuest` takes board quests too; no slot used): its card/sheet shows where the item is — （持っている） / （商店に売っている） / （持っていない） (`haveLabel` in questboard.js) — with 納品する or 購入（金貨N）して納品 (`buyLabel`) instead of 受ける. **固定クエスト** (`FIXED_QUESTS`, ids saved — never rename) = named givers with story `lines`/`done`, `appear` condition (`reported`/`cleared`/`open`/`found`/`claimed` = an earlier fixed quest reported — progress-based), `goal` (`kill` keys×n / `floor` dungeon+n / `clear` dungeon / `soul` / `chest`), `reward` in 戦果 units of `ref` dungeon (floored at 70% of the deepest open dungeon's) + red/embers/souls, optional `opens` (side dungeon unlocked on accept). One-time; **counts toward the same `FREE_CAP` 5 slots** until reported (`questSlotCount` = free active + fixed not yet claimed; `questCapRefused` guards both kinds) and, while not yet achieved, can be abandoned (`abandonQuest` deletes `fixed[id]` → it returns to the tavern as an offer; a side dungeon it opened stays open). State `G.quest = {board, active, fixed:{id:{state,progress}}, seen, seq}` (`questState()`); progress via `questProgress(type, key, n)` hooks (kill in `endBattle`, soul in `grantSoulQuiet`, chest in `openChest`, floor in `descend` + `enterDungeon`, clear in `commitDungeonClear`). Claims: both go through `UI.playStoryChain` (`place: "tavern"`, `who: {name, sub, art}` = the giver's name/title with the quest's subject — slain monster / delivered item / soul / chest / stairs — in the portrait frame; reward rows may carry a `tag`) and count `G.stats.questsDone` (勲章). **Free-quest variety** (the report is a core loop — keep it from going stale): 20 givers `NPCS` (index saved as `q.npc` — append only; each has `thanks`/`regular`/`bond`[3]/`tip` lines, `kid` = never posts adult-voiced texts), 60 offer texts in `KILL_/SOUL_/CHEST_/REACH_/DELIVER_TEXTS`, each with a paired report line `done` and a `who` list of givers whose voice fits (deliver texts may be `gear`/`misc`-only); `pickText` avoids repeating a giver on one board; the resolved `name/text/done/vars` are saved on the quest. `composeReport(q, count, {tip, bond})` = opener (by type) + `done` + the giver's thanks (regular lines once familiar) + tip line + closer. Familiarity `G.quest.npcs[i]` = reports per giver → `npcBondLabel` 顔見知り/顔なじみ/なじみ/古なじみ (shown in the offer sheet); milestones 3/6/10 then every 5 add `BOND_GIFTS` (rare/epic souls, embers); `TIP_RATE` 22% adds a 心付け (`questTip`: 30-50% of the gold/✦Soul). UI: `src/ui/questboard.js` (cards, detail sheet, hub chips) — tavern page segments 受注 n/5 / 掲示板 / 噂と顔ぶれ (`UI.openTavern(seg)`), the hub shows a 「酒場の依頼」 strip, the departure sheet marks each dungeon an active quest targets with a 「! 依頼」 badge next to its name (`questHereCount` → `.dp-qmark`, 「依頼×N」 for several; free quests by `q.dungeon`, fixed by `fixedQuestTargets` = `goal.dungeon`, or for kill goals every dungeon whose bands/boss hold a target — metal targets from layer 3; soul/chest quests mark nothing, like free ones) and tags side dungeons 依頼の迷宮 (`questHereNote`). In a dungeon, the 階の情報 sheet (`openFloorInfo` in dungeonhud.js) lists 「ここで果たせる依頼」 = `questsHere()` (game.js): active quests that can progress here — kill whose target is in this dungeon's roster (`questKillHere`), floor/clear of this dungeon, soul/chest anywhere; deliver never — plus done ones awaiting report.
- **勲章 (`ACH_SERIES` in game.js, 王宮「勲章」 = `renderAch` in `ui/palace.js`)** — 受領数はやり込みの指標なので**どの系統も段が尽きない**: 系統 = `series(key, rows, desc, value, {more, id, secret, dynamic})`、手書きの段 (旧来の ID) の先は `more(v, k)` の刻みで延々と続く (ID `${key}#${k}`、名前「〜・其の二」、報酬は最後の段の +30%/k・赤い魂 +1/k 上限 20)。回数 (潜入・撃破・宝箱…) / 中身の数 (迷宮・図鑑・出来事・主の種類・SR/LR 図鑑…) / 「〜ごとの極め」(3回・10回踏破した迷宮の数 `dr3_`/`dr10_`、10体・100体倒した魔物の種類 `mk10_`/`mk100_`、ランク2〜5・Lv100 に育てた職業の数 `rank2`-`rank5`/`jl100` — 段は `RANK_STEPS` 1/2/3/4/5/6/10/15…50種で共通、その先も5種ずつ (職業はこれからも増えるので、いまの職業数を越える段も置く。旧 ID await6/jrank3-5 を引き継ぐ)。職業発現 `hyb` だけは最後の段が職業の総数に合わせて動き、達成まで伏せる) の3種で、迷宮や魔物が増えるほど伸びしろが広がる。勲章の間には系統ごとに次の段だけ (`achNext`)、札に「いま N」を添える。勲位 `medalRank` = 受領数で決まる位 (金剛章の先は100ごとに「・其の二」…)。報酬の物差し: 迷宮の初踏破の報告 (100〜350G・赤2〜10) を超えない — 序盤 30〜150G。段の ID はセーブに残る (変えない・消した段は受領数に残るだけ)。
- **`combat.js`** — pure combat logic: `Battle` state machine (per-actor AGI-ordered turns), `SPELLS` (defined in `skilldefs.js`), enemy construction (`makeEnemy`/`spawnCardEnemies`/`spawnBossEnemies`/`spawnMimic`, up to `MAX_ENEMIES`=6 per encounter). ATK=physical damage, VIT=damage reduction, AGI=turn order/evasion, INT=attack-spell power, PIE=heal power, LUK=crit. Equipment, souls, and buffs all add to/multiply these same keys. - **`pricing.js`** — **装備の値段は性能で決まる**: `repriceEquipment(ITEMS)` (game.js が起動時に ITEMS 統合直後に呼ぶ) が全装備の `price` を付け直す。性能点 = 能力値 × 共通の重み (`STAT_W`: ATK/VIT/AGI 1, INT/PIE 0.7, LUK 0.6, HP 0.15, MP 0.25, 会心 100) × 属性・状態異常耐性・追加効果の上乗せ (`featureMul`) + %補正・戦闘効果の固定点 (`EFF_PTS`/`MULT_PTS`、lv に依らない)。その部位の標準品 (defs.js ビルダー既定値, `REF`) が同じ点になる lv を逆算して従来の価格曲線 priceOf(lv) に乗せるので、標準品の値段はほぼ据え置きで「性能が同じ品は同じ値段・どこも同等以上の品は必ず高い」が成り立つ (レア度での上乗せは無し)。ビルダーや items.js に書いた `price` は装備では上書きされる (道具・収集品はそのまま)。値段 0 の品 (呪いの妖刀) は対象外。装備を足したら px チェック (同じ部位で支配する品が安くないか) を回す。

### 装備のレア度 (5段階) — `src/rarity.js`
Every equipment item has `rar`: `c` コモン(白) / `uc` アンコモン(緑) / `r` レア(青) / `sr` スーパーレア(橙) / `lr` レジェンドレア(赤). **Names are colored by rarity everywhere** (`itemNameEl` / `.rar-*` classes; unidentified items still show the color). Classification is assigned in `catalog/index.js` from the source: rank-file standard gear → lower-lv of each pair `c`, higher `uc`; unique one-offs (weapons/armor/gear.js) → `r` (stats ×`RARE_STAT_MUL`); exclusives `x_` + legends → `sr`; `lr_` → `lr`; per-layer showcase items (`catalog/layer1.js` … `layer5.js`; layer 4 = 16 SR + 6 LR, lv 33-58, light/fire leaning vs the fort's dark prison and wind storm; layer 5 = 16 SR + 6 LR, lv 43-68, fire/wind + ailment resists vs the forest; its LR carry `lr: 5` like the job LR tier, so `lrPool` and the ×20 appraisal check `it.layer` first) carry their own `sr`/`lr` **and `layer`** — `pickOfRarity` skips items whose `layer` is deeper than the current `battleLayer()`, and `lrPool` admits tier 1-4 LR (`lr` = its layer) only from that layer on and within `lootCapR`. Layer-2 water enemies are best resisted by **earth** `eDef` (defense must *beat* the attack element — a same-element eDef does nothing); layer-3 earth enemies likewise by **wind** (`layer3.js` leans on wind eAtk/eDef). Rule for every layer item (layer files + named trophies): its `eAtk` must beat an element that ≥10% of that layer's foes (world rosters incl. the dungeon aura) carry, its `eDef` must beat such an attack element (light↔dark: only light eDef cuts dark attacks, and dark eAtk does nothing to dark foes — layer 1 is almost all dark), its `aRes` kinds must be inflicted by some foe of that layer, and `bRes` needs a breath/spell user there (layer 4 has none, and of the ailments only paralysis). Base items.js gear defaults to `c` (game.js after the ITEMS merge).
- **Drop pipeline** (`pickLoot(opts)` in game.js; all loot goes through it): 8% collectible, else **LR time roll**, else `rollRarity(rarityUp(opts))` then `pickOfRarity` from the R window (centerR ±2, widening, then downgrading). **Base R = `lootBaseR()` = `ceil(cfg.lootLv[1]/10)` (= the layer: D1-5 → R1 … D96-100 → R20; extra dungeons / the abyss only need a `lootLv`).** Modifiers (elite/rare/chest rank/mimic/special floor/mutator) push the center up, but center and window are hard-capped at **`lootCapR()` = base + `LOOT_R_HEADROOM` (2)** — layer 1 never drops gear above R3 (lv30); tier-1 LR are gated by the same cap. (R used to be the dungeon number, which let D5 drop R3-7 gear and trivialized layer 1 — don't key loot on `dungeonNumber`.) `rarityUp` = chest rank / elite / mimic / black chest / special floor / mutator **+ depth (`layerRarityUp`)**. Items usable by someone in the party are weighted ×3.
- **Curated drop pools ("少数精鋭")**: C〜R items flagged `noDrop` in `catalog/index.js` are excluded from drops (not deleted — still in catalog/codex/saves): 1 standard item per band per slot-type (C/UC alternating), `RARE_PER_BAND` uniques per band. SR/LR are untouched. Keep this when adding items: new commons/uncommons should replace, not pile up.
- **LR is time-based, not per-drop**: `G.lrClock = {since, pend}` accumulates *active* play time (visible + input within 2 min) × `lrLayerFactor(layer)` (layer 1 ≈ 0.02 → LR almost never drops in layer 1). At each equipment drop, `p = 1 - exp(-pend / (M × LR_HAZARD_K))` with pity at `M × LR_PITY_K`, where `M = lrIntervalH(推奨Lv)` = 5h up to Lv31 → 4h at Lv70 → 3h from Lv107 (cap; the old D15/D33/D50). LR are 1点もの (`G.lrOwned`, marked in `runGainItem`); `refundLR` restores the pity if an LR couldn't be carried. The old flat-2% exclusive layer was removed.

### Dungeon registry (`src/dungeons/`) — generated dungeons + rank-tiered bestiary

- **`bestiary.js`** — ALL monsters, organized by **rank 1-10**. - Monster IDs are **namespaced** (`bs_troll`, `cm_slime`) and treated as **append-only** — IDs are persisted in saves and codex, so renaming/removing them breaks existing saves. Add new IDs rather than repurposing old ones.

- Every monster needs a valid `artKey` (one of `ARTS`) — `defMonster` throws otherwise. See **Monster individuation** below for the unique-design rule.
- **Layer 1-4 HD monster art (`hd_*` in `schema.js` ARTS)**: layers 1-4 use hand-built high-res prototypes (regulars 96×96, layer boss/elites 112×128; dark low-key ramps, upper-left key light, no outline — shadow-side edge is the darkest tone, cold rim on the back edge, `o` = pure black for sockets/mouths). Layers 2-4 (69) are generated by **`tools/hdart/`**: a small SDF ray-marcher (`sdf.mjs`: sphere/ellipsoid/cone/tube/box/slab/cyl/torus + smooth union/sub/displace/paint, soft shadows, AO, point lights, Bayer-dithered ramps, inner depth lines, rim) plus 2D finishing passes (teeth via `fangs`, drips, particles). For a new layer add its `HEAD` entry in `integrate.mjs` (layer 3's block sits after the event block), then bump `sw.js`. Shared ground/lighting per layer: `lib.mjs` = layer 2's sewer water (`puddle`/`ripples`), `mine.mjs` = layer 3's mine (`rubble` gravel bed + fallen rocks, `pebbles`, sparse `dust`, `cracks` ridged-noise displacement for rock, `tri` for teeth/claws/crystal facets, grey-blue `RIM`), `forest.mjs` = layer 5's mist forest (above), `fort.mjs` = layer 4's fort (`flagstones` cut-stone floor + toppled masonry, `arrowShafts`, `ash` (grey ash / `ember` sparks), `grit`, `flutter` cloth wave, moonlit blue-grey `RIM`). Isolated single-pixel particles get the in-game 1-dot black halo, so keep them sparse.
- **金属の魔物 (メタル系・マスコット, `mt_*`)**: 銀業 `mt_silver` / 金業 `mt_gold` / 銀業の王 `mt_king` (`METAL_MONSTER_DEFS` in bestiary.js, def field `metal` = tier 1-3 → `METAL_TIERS` in schema.js: `hp`/`hpRank`/`evade`/`flee`/`agiMul`/`soulMul` 10/25/60/`goldMul`/`max`/`layer`/`w`). ### Monster individuation (固有デザイン・特徴・スキル) — the per-monster identity rules
The goal (per design direction): **every enemy is individually distinctive**, both visually and mechanically. Two rules enforce this — apply them whenever adding or refining a monster.

**Rule 1 — unique art per monster (no palette-swap clones).** Each monster gets its **own `ARTS` prototype**. Do *not* differentiate two monsters by `palette`/`tint` alone (e.g. a green-tinted `kobold` for a goblin) — that reads as a recolor, not a design. `palette`/`tint` is acceptable only for *minor* variants of the *same creature concept*, never to dress up a different creature. Authoring workflow for a new prototype:
  1. Add a `{ palette, art }` entry to `ARTS` in `schema.js`. `art` is an array of rows (variable row length allowed — right side is padded transparent; `.` = transparent). Convention: `o` = outline (darkest), light source upper-left, ~3 tones per material. Resolution may be mixed (old 12×12 / new ~16-32px); `drawSpriteFit` normalizes display size.
  2. **Verify the silhouette before committing** — you can't see a canvas headlessly, so render an ASCII preview: map each non-`.` glyph to a block (`o`→`##`, others→glyph×2) and print the grid. Iterate until the shape reads clearly and is distinct from its neighbours.
  3. Set the monster's `artKey` to the new prototype and **remove any `palette`/`tint` override** so it uses the prototype's own palette.
  4. Check for clones: no two monsters in the same dungeon band should share a prototype. (Quick check: import `BESTIARY`, group the roster by `m.art` signature, flag any group >1.)

**Rule 2 — give each monster a distinctive combat trait (TRAITS).** `schema.js` defines `TRAITS` (the shared vocabulary) and `monsterTraits(m)` / `monsterTraitKeys(m)` (normalize a def's fields into an ordered trait list). The monster codex shows these traits (固有ドロップ was abolished — see below). Author traits on the def via:
  - **`ability`** (single special action, used ~25-30% of turns by `combat.js` `enemyAct`): `poison` / `paralyze` / `stone` / `drain` / `soulSteal` / `goldSteal` / `critical` / `breath` / `sleep` / `charm` / `confuse` (e.g. 墓火=混乱, 霊蝙蝠=眠り, 提灯アンコウ=魅了, 汚水のもや=眠り, 毒マンドレイク=混乱). Set explicitly to override the race-default auto-assignment in `game.js` (`RACE_ABILITY`); set `ability: null` to suppress it. **Brutal abilities (`drain`/`soulSteal`/`critical`/`stone`) are gated to rank ≥4** — don't put them on low-rank enemies.
  - **`role`** (`summoner` + `summonKey` calls allies mid-battle / `healer` heals wounded allies / `guard` + optional `escort` body-blocks). Solo bosses can use `summoner` (spawns adds) but `healer` is wasted on a solo boss.
  - **Passive combat fields** (read by `combat.js` `makeEnemy`/`_physical`/`_cast`/`_startRound` and `spawnCardEnemies`): `physResist` / `magResist` (**耐性ランク 1-3** — `RESIST_RATE` in schema.js: 1 = 50%軽減「効きにくい」, 2 = 75%「ほとんど効かない」, 3 = 100%「無効」; `defMonster` throws on anything but 1/2/3, on rank 3 for bosses/elites, and on dual phys+mag resist above 2, so every enemy stays killable; `monsterTraits` shows 「物理耐性N」+ the rank text; immune hits return `immune:true`/0 dmg, show 「無効」, and auto combat skips/stops on phys-immune foes. Skills with `pierce` (防御無視) **and critical hits (会心, incl. sure crits and the party's counter crits)** ignore physResist 1-2 entirely in `_physical`/`_tryCounter` (rank 3 = 物理無効 still blocks them; magic-weapon hits judged by magResist are unaffected). Foes that magic must carry get less HP: `resistHpMul(m, strong)` in schema.js keys on physResist only (dual phys+mag resist too; magResist alone never lowers HP): regulars physResist 2 → HP ×0.7, 3 → ×0.4; bosses/elites (`boss`/`elite` flag or `strong`) 2 → ×0.8, 3 → ×0.5; applied in combat.js `makeEnemy`/`spawnRanked`/`spawnMimic` and the codex HP. Depth curve: layers 1-5 mostly rank 1 (rank 2 rare), mid layers mostly 2, rank 3 from layer 9 and common from layer 15 — keep that curve when authoring), `magWeak` (>1, attack-spell damage multiplier — "魔法に弱い"), `regen` (0–1, self-heal per round), `swift` (bumps AGI +4), `evasive` (+15% physical dodge), `pack` (spawns ≥3). `defMonster` whitelists these — add new fields there *and* to `monsterTraitKeys` if you introduce more.
  - Aim for a **1-2 trait headline** per monster that matches its flavor text, and keep traits varied across a band (don't make every rank-1 enemy poison). The touchstone examples: the "物理耐性 + 魔法弱点" slime, the "招来" rat-caller, the "ブレス" dragon (rank ≥6).

**固有ドロップは廃止 (drop system removed)** — except the 首級 of 名のある強敵 (below, user's decision). Monsters no longer carry `dropNormal`/`dropRare`. Post-victory chests roll generic loot from the dungeon's `lootLv` band (`rollGenericDrop` in `game.js`). The codex "落とすもの" panel was replaced by a "特徴・スキル" panel driven by `monsterTraits`. Don't re-introduce per-monster drop tables.

**Progress:** **All ranks 1-10 are fully individuated** — every monster (regular/role/boss/elite) has a hand-tuned trait headline and a concept-appropriate sprite. New prototypes were authored to fix concept mismatches (a different creature wearing another's silhouette): rank 1 `caverat`; rank 2 `soldier`/`zombie`/`gnoll`/`hound`/`gobshaman`/`piper`/`gobchief`; rank 3 `werewolf`/`scorpion`/`darkelf`; rank 4 `gargoyle`/`gorgon`/`deepsahagin`/`banshee`/`cultist`/`samurai`; rank 5 `dullahan`/`ironknight`/`fireserpent`; rank 6 `stormgiant`/`wyvern`; rank 7 `vampire`/`reaper` (+ `stormwyvern` reuses `wyvern`); rank 8 `crystalgolem`/`necromancer`; rank 9 `angel` (+ `soulreaper` reuses `reaper`); rank 10 (`primalserpent` reuses `fireserpent`). Brutal abilities (`critical`/`drain`/`soulSteal`/`stone`) are only on rank ≥4. Remaining shared prototypes are intentional **same-concept tint variants** (e.g. two orcs, two armored knights, lich/ghost/skeleton/mandrake/ogre/dragon/imp families, bosses-in-different-dungeons) — consistent with the accepted bar. When **adding new monsters**, keep this bar: give a concept-mismatched newcomer its own `ARTS` prototype (don't recolor an unrelated one) and a hand-tuned trait. Note: elite (`el_*`) monsters carry `rank = band+2` but spawn in the lower band's dungeons (an elite of `rank R` appears in `rank R-2` dungeons), so group by spawn-dungeon, not `.rank`, when checking co-appearance. A few single-in-band creatures still ride a related-concept prototype by choice (e.g. `chimera`/`griffon`/`naga`/`godslayer` on beast/harpy/sahagin/orc) — fine as accepted variants, but candidates if a future pass wants even tighter individuation.

### Item catalog (`src/catalog/`) — unique items, additive-by-design
- **`defs.js`** — shared item `ARTS` (12x12 shapes per weapon subcategory / armor type / misc trinket) and builders `W/S/A/H/F/G/R/M/U` (weapon/shield/body/head/feet/hands/accessory/misc/usable). Builders derive atk/def/price/rank from the hidden item level and validate input (throw on bad cat/shape/lv/desc).
- **`weapons.js`/`armor.js`/`gear.js`/`misc.js`/`legends.js`** — the hand-written unique-item catalogs (100 weapons, 50 shields, 50 body, 50 head, 50 feet, 18 hands, 8 accessories, **100 収集品/collectible loot (exactly 10 per rank band R1-R10, grouped by `ceil(lv/20)`)**, a few potions, plus 11 mythic legends at lv165-200). **`index.js`** merges them into `CATALOG_ITEMS` (throws on duplicate IDs); `game.js` does `Object.assign(ITEMS, CATALOG_ITEMS)` at load.
- Item IDs are prefixed (`w_`/`s_`/`a_`/`h_`/`f_`/`g_`/`r_`/`m_`/`u_`) and **append-only** (saves/codex reference them). Names are unique one-offs — there are no rank-prefix "二つ名" items anymore.
- Every item has a **hidden level `lv` (1-200)** matching the 100-dungeon `lootLv` bands (lv1-20 = mundane gear, 165-200 = mythic): dungeons define a `lootLv: [min, max]` band (interpolated by floor depth) and `game.js` rolls loot with a gaussian window around that center plus a global decay, so higher-lv items are rarer everywhere. Post-victory loot is rolled generically from the current dungeon's `lootLv` band (`rollGenericDrop`; per-monster 固有ドロップ was removed). Display rank (R1-R6) derives from lv via `lvToRank` (thresholds 20/45/80/120/165). When adding items, keep every ~20-lv bucket populated or loot rolls in that band degrade to the `herb` fallback.
- Slot `misc` (収集品: collectible loot) can't be equipped or used; collectibles are either sold at the shop or **奉納 (donated) at the 王宮 宝物庫 (treasury)**. The old `mat`/貴重品 slot (空の魂) was removed. ### Element / affinity system
Six elements + `none`, defined in `schema.js`. Advantage cycle is **火→風→土→水→火** (fire→wind→earth→water→fire); **light↔dark are mutually advantageous**. Offensive spells carry an `element`, enemies carry `element` from their monster def.

**Elemental attack/defense stats (属性攻撃/属性防御):** items can carry `eAtk`/`eDef` (`{el, lv}`); `recalc` aggregates them per member into `member.elemAtk`/`member.elemDef` (same element stacks, capped at Lv2=◎; different elements don't mix — strongest wins). `elemDmgMult(aE, aLv, tgtElem, tgtDef)` in `schema.js` is the single damage-multiplier entry point used by `combat.js` (`_physical` and the `atk`-spell branch): the attack side compares the attack element vs the target's innate element (Lv1=◯ ±50%, Lv2=◎ ±100%), the defense side compares the defender's `elemDef` vs the incoming attack element (**reduction only** — when the defense element has the advantage it cuts damage by 25% (Lv1) / 50% (Lv2), but a disadvantageous element never increases incoming damage). Spells act as Lv1 unless the caster's `elemAtk` matches the spell element. The legacy flat `elemMult` remains for reference but combat uses `elemDmgMult`.

### State & persistence
- All runtime state hangs off the single global `G` in `game.js`. `state` field switches the active screen (`town`/`board`/`battle`/`over`).
- Save key: `dos-save-v7` in `localStorage` (v7 = the dungeon map / master story; earlier history below) (v1-v3 saves are intentionally orphaned — v4 made souls a party-shared pool with vessel dolls, primary+sub-soul slots, and the Order). Only the fields in `SAVE_FIELDS` are persisted (transient animation state is excluded).
- Saving uses **`refSerialize`/ref-hydrate**: a custom serializer that encodes shared/circular object references as `{$r: index}` so object **identity is preserved** on load (a single soul object referenced from multiple places stays the same instance). When adding state that relies on shared references, keep it inside this graph rather than re-cloning.
