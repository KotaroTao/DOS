# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-page, build-free browser RPG (ウィザードリィ風／魂の迷宮 - Dungeon of Souls). Pure HTML + ES Modules + Canvas — **no bundler, no package.json, no npm, no test runner, no lint config.** All monster/hero/item art is drawn programmatically as pixel art on Canvas. The only image assets are user-provided illustrations under `art/`, normally converted to true pixel art (one dot = one pixel, palette-reduced) — currently `art/op_dolls.png`, the opening's 人業 scene. Exception (by user request): `art/mansion_irene.jpg`, the 人業の館 mistress イレーヌ, is the user's painted illustration used as-is (1172×420 JPEG, no pixel conversion; drawn smoothly, not `pixelated`) under the 隊 tab and in her greeting scene — `keeperPanel` in `src/ui/party.js`, fills only the height left over and folds away via container queries in `ui-party.css`); list each in `sw.js` ASSETS. Ships as a PWA (manifest + Service Worker, offline-capable).

The game has a town hub, 100 generated dungeons (each with a unique boss), a souls system, codices, quests, and an element/affinity system. When README and code disagree, trust the code.

## Running & "building"

There is no build step. Because it uses ES Modules, you must serve over HTTP (not `file://`):

```bash
python3 -m http.server 8000   # then open http://localhost:8000/
# or: npx serve .
```

Deploy is automatic: pushing to `main` triggers `.github/workflows/pages.yml`, which uploads the repo root as-is to GitHub Pages (https://kotarotao.github.io/DOS/). No build/test job runs in CI.

### Verifying changes without a browser
There is no test suite. To sanity-check JS edits, use Node:
- Syntax: `for f in $(git ls-files 'src/*.js'); do node --check "$f"; done`
- Module load / logic: a DOM-stub harness (`globalThis.document/window/localStorage/AudioContext` fakes) can `import('./src/game.js')` headlessly to catch load-time errors, and pure logic modules (`combat.js`, `dungeons/*`) can be imported and exercised directly. When testing combat in isolation, first `Object.assign(MONSTERS, DUNGEON_MONSTERS)` because that merge normally happens in `game.js`.

### Service Worker cache — bump on every shipped change
`sw.js` caches assets under a versioned key (`const CACHE = "dos-vNN"`). **Whenever you change any shipped file (JS/CSS/HTML), bump this version** (e.g. `dos-v53` → `dos-v54`), or returning players keep the stale cached copy.

## Architecture

### Module layout (`src/`)
- **`game.js`** — the hub. Owns the single global game state `G`, the main loop, input, all screen rendering (town/board/battle/status/codex overlays), and the bridge between board exploration and turn-based combat. By far the largest file; most features touch it.
- **`board.js`** — maze generation. Edge-walls (walls live on the *boundary* between cells, not as cells), dead-end event placement, stair placement, return portals (`type:"portal"` — guaranteed on every 5th floor, 20% chance elsewhere; stepping on one or killing the boss are the only ways back to town), and poison-floor tiles (`type:"poison"`, corridor cells, `cfg.poisonRate` from the dungeon generator — rank 3 band and deeper).
- **`traps.js`** — pure trap/chest-rank data: `TRAPS` (24 trap defs, trap rank 1-3 — rank gates appearance by dungeon rank, so all 24 appear from dungeon 21+), `pickTrap(dungeonRank)` (weights dangerous traps heavier in deeper dungeons), and chest ranks 1-5 (`CHEST_RANKS`/`rollChestRank` — deeper floors/dungeons roll higher). Execution/animation lives in `game.js` (`springTrap` applies effects for floor traps and chest traps alike; `disarmNeed(chestRank)` makes disarm difficulty a function of dungeon rank × chest rank; higher chest rank also boosts loot in `chestContents`).
- **`telemetry.js`** + **`baseline.js`** — 戦闘バランス調整の材料集め (挙動には影響しない)。`telemetry.js` = テスト記録: 設定「自動化・データ」→「テスト記録」で ON にすると、迷宮ごと (`D10` / 奈落は `A3`) に隊の様子 (1階到着 `f1`・最後の階 `last`・踏破 `clear` 時の各人業の職/Lv/能力値) と戦闘の集計 (種類 n=通常/e=精鋭・ミミック・出来事/b=主 ごとに 勝/逃/全滅・ラウンド・先制/奇襲・物理の試行/回避/見切り (味方→敵 `pa/pe/pp`・敵→味方 `ea/ee/ep`)・手番で味方が先だった組 `of/op`・逃走 `ft/fo/fs`・与/被ダメ・戦闘前後の隊HP割合・隊平均/敵最大AGI) を `localStorage['dos-testlog']` (セーブとは別、はじめからでも消えない) に溜め、「書き出す」で要約+JSON をクリップボードへコピーする。game.js のフックは `startBattle` (`tlBattleBegin` → `G.battle.tl`)・`animateResult` (`tlHits`)・`endBattle` (`tlBattleEnd`)・`newFloor`/`commitDungeonClear` (`tlSnapshot`)、命中・手番・逃走の数は combat.js の `Battle.tally` (`_physical`/`_startRound`/逃走) が数える (乱数は消費しない)。`baseline.js` = **基準の隊** `PARTY_BASELINE` (「レベル上げをほぼせず普通に進めた隊」の迷宮ごとの平均能力値。テスト記録の実測で1層ずつ行を足す) と `baselineAgi(progressX(n, floor, floors))` (実測点を直線で結び、前は (x=0, 7) から、先は +2.4/迷宮で延ばす)。逃走判定 (下記) が使い、AGI 仕様の刷新 (敵 AGI = 基準AGI × 速さ係数) でも戦闘から読む予定。
- **`events.js`** — 迷宮のイベント (出来事マス `type:"event"`, `cell.evId`). **63 events: 33 common (`c01`-`c33`, any layer) + 10 per layer for layers 1-3 (`l1_*`/`l2_*`/`l3_*`)**, choice-based with a free 「立ち去る」 (the cell stays; you can come back) — **except 極 (mythic)**, which have no choices: `gift(A, cell)` grants a permanent boon the moment the cell is stepped on (`once: true` per save, `boon` text for the codex; effects in `EV_BOONS` → `G.events.flags` `will`/`blackCat`/`sewerMap`/`temper`, read by game.js `evBoon` in `runGainSoulPts`/`evBattleStart`; `loadGame` grants them to saves that met the old choice-based versions). **Never offer a choice that does nothing** (it would duplicate 立ち去る) — hide choices with no effect right now (e.g. heals when nobody is hurt). Revival events: c31 生命の雫 (common, `cond` = someone dead, one member at HP1), c32 闇医者 (uncommon, inn cost ×3 heal / mansion repair cost ×3 revive, `A.revive`/`A.deadList`), c33 神聖なる泉 (rare, deep, revives all + full HP/MP). Tiers `EV_TIERS` (常 common / 稀 uncommon / 秘 rare = once per run / 極 mythic = once per save) — `pickEvent` first draws the tier by `share` (62/28/8/2, renormalized over the tiers eligible here), then an event in it (that layer's own events ×1.5). Gating fields: `layer`, `minFloor`, `deep` (back half of the dungeon), `minDn`, `maxSkip` (floors needed below), `cond(A)`; D1 only rolls common. Placement: `evNewFloor` in game.js (called from `newFloor`) puts at most one event per floor (`EV_FLOOR_RATE` 0.42, D1 0.25) on a dead end; not in the abyss. Rewards are sized in **「戦果」 units = one ordinary battle's gold/✦Soul for this dungeon/floor** (`evUnit`) and go through the existing pipelines (`pickLoot` with `noLR`, `acquireSoul`, chests via `chestHere` → `askOpenChest`), so `lootCapR` still holds; events never give LR or Red Soul. **events.js never imports game.js** — every board/battle/reward operation goes through the `evApi` object (`A`) built in game.js. Fights use `A.fight(cell, specs, tag, {noChest, opening})`; specs are resolved to concrete keys and stored in `cell.evFight` (serializable), `endBattle` marks `won` and, after the results sheet, calls `eventFightWon` → the event's `onWin` (multi-stage fights chain from there; fleeing leaves `evFight` so revisiting offers a rematch). State: `G.events` (saved: `seen`/`picks`/`once`/`flags`/`fresh` — the 見聞録 codex segment in `ui/palace.js`, plus permanent flags `sewerMap`, `bossWeak[layer]`, `lore`), `G.run.ev` (this run: `mods` like `{enemyMul}`, preempt/ambushNext/startHeal/bomb/crit/edef/saves/ruby/noBeast/mapChest/bounty…), `G.board.ev` (this floor: `mods` with `dmgMul`/`prey`, oath/miner quests checked by `evProgress`). Run/floor `mods` are merged into `activeModifierDefs` (so `enemyMul`/`chestRankUp` work like mutators); combat buffs are copied to party actors at battle start (`evBattleStart`: `_evDmg`/`_evPrey`/`_evCrit`/`_evEDef`/`_evSave`, read by combat.js `evDealMul`/`edefOf`/`_die`). 鍛え直し sets `item.forge` and `applyForge` (items.js) — re-applied after `reflattenItemStats`; `itemName` appends ＋N. Board icon `ICONS.event` (violet rune stone). **Event-only monsters** (`EVENT_MONSTER_DEFS` in bestiary.js, flag `evOnly` → excluded from `RANK_POOLS`/dungeon rosters, listed in the codex 「その他」 tab via `CODEX_OTHER`): a fight spec `{ key, ranked: n }` spawns them through combat.js `spawnRanked` at **(this floor's top regular rank, `mimicRef().rank`) + n** on the `rankStats` curve (solo HP ×2.2), so they stay one rank above the floor in every layer — e.g. c19 「檻の中の人業」's 檻番の獄卒 `bs_cagewarden` (`ranked: 1`). Their HD art lives in `tools/hdart/event/` (`node tools/hdart/run.mjs event --apply` writes the 「出来事の魔物」 hd_* block after layer 2's). `floorFacts` in dungeonhud shows active event effects (`game.eventFacts`). **Adding an event**: append to `EVENTS` (ids are saved — never rename/reuse), keep the risk↔reward ladder (common ≈ 戦果1-2, uncommon 3-5, rare 8-12, mythic = permanent/lore), always end a choice with `A.done(cell)`/`A.back()`/a next screen, and run the headless sweep (every event × every choice) before shipping.
- **`combat.js`** — pure combat logic: `Battle` state machine (per-actor AGI-ordered turns), `SPELLS` (defined in `skilldefs.js`), enemy construction (`makeEnemy`/`spawnCardEnemies`/`spawnBossEnemies`/`spawnMimic`, up to `MAX_ENEMIES`=6 per encounter). Returns plain result objects; **all animation/SFX lives in `game.js`** (`combatStep` drives `Battle` and renders the results).
  - **Stats are unified into six attributes** (`atk`/`vit`/`agi`/`int`/`pie`/`luk`, plus HP/MP) — there are no derived こうげき/ぼうぎょ/すばやさ/AC values. ATK=physical damage, VIT=damage reduction, AGI=turn order/evasion, INT=attack-spell power, PIE=heal power, LUK=crit. Equipment, souls, and buffs all add to/multiply these same keys. Monster *defs* still author `atk/def/spd`; `makeEnemy` maps them to `atk/vit/agi` at spawn. Old saves (item/actor `def`/`spd`/`ac`) are migrated on load by `migrateLegacyStats` in `game.js`.
  - **逃走 (`Battle.fleeChance(actor)`)**: 逃走を選んだ本人の実効AGI (バフ/デバフ込み) と、生存する敵の実効AGI平均 × `fleeK` (= 追跡AGI。主がいれば ×1.3) の比で決まる: `55% + 35% × log2(本人 ÷ 追跡) + 逃げ足 (fleetFoot +30% / 結社 +30/45/60%、高い方)` → 5〜95%。`fleeK` は game.js `fleeScale()` = その迷宮・階の `baselineAgi` ÷ 出現表の雑魚の素のAGI中央値 (敵の AGI は味方よりずっと小さい規模なので揃える)。`noFlee` (閉ざされた退路) は 0%。戦闘の「逃走」ボタンに手番の者の成功率を表示する。
  - **Rows (前衛/後衛)**: on both sides, array index 0-2 = front row, 3+ = back row (`Battle.isBackRow`; a side whose front row is wiped has its back row promoted). Back row deals AND receives ×0.5 **physical** damage (`_rowMul`, applied in `_physical`/counter — attack spells & breath are exempt), and is targeted less by enemies (`_pickPartyTarget` weights front 3 : back 1, × taunt 3). Player physical reach is gated by **weapon range** (`weaponRange` in items.js: 近=enemy front only / 中=enemy back reachable only from own front / 長=everything; spells unrestricted) via `attackableEnemies`, which filters `targetOptions`, 居合/残心 retargets, and the tap/auto targeting in `game.js`. Party order = formation; reordering UI lives in `renderMansionParty` (game.js).
- **`sprites.js`** — `MONSTERS`, `HERO`, `ICONS` pixel-art definitions and `drawSprite`. `MONSTERS` starts with a base set and is **augmented at load time** by `Object.assign(MONSTERS, DUNGEON_MONSTERS)` in `game.js`.
- **`items.js`** — base equipment/consumable items, item categories (`ITEM_CATS`, `WEAPON_CATS`), 8-slot equip logic (`recalc`, `equip` — `recalc` also aggregates elemental attack/defense from gear), restrictions (alignment/class/two-handed/cursed). Weapon range (`weaponRange`/`RANGE_LABEL`): derived from `cat` (槍=mid, 弓=long, others=near), overridable per item via `range`.
- **`souls.js`** — souls/job system data/logic. **The soul is the entity; the doll is just a vessel.** Progression is a **party-shared pool** held in game.js as `G.souls = {clsKey:{count, level, exp}}` (one entry per of the 36 jobs, shared across all dolls); `souls.js` reads it via a module ref set by `setSharedSouls(G.souls)`. A doll has `primary` (the job soul it wears → full stats/skills/passives) and up to `MAX_SUBS` (=2) **`subs`** (サブ魂 slots, `{uid, picks:[{skill}|{passive}], picked}`: borrow **any** skills/passives that soul has learned (`soulLearnedSkills`/`soulLearnedPassives`), up to `subPickCap(soul)` = by that soul's rank R1-2:1 / R3-4:2 / R5:3 (`subPickCapOfRank`); `subPicks(sub)` normalizes/migrates the old `{skill, passive}` form, `toggleSubPick` adds/removes (cap 1 = swap); an empty, never-edited sub defaults to its last learned skill; slots open at 10/40 cleared dungeons; **adds 30% (`SUB_STAT_RATE`) of that sub-soul's `jobStatsOf` to the doll**). `JOB_SIGNATURE[k]` (each job's lv-40 skill) is now display-only. **魂の残火** (`G.embers`) raise a soul instance's level cap by +1 (`capBonus`, `raiseSoulCap` in game.js) at a cost by job rarity (`EMBER_PER_CAP`/`emberCostOf`: common 1 / rare 2 / epic 3 / legend 5). `count`→rank via `soulRankFromCount`/`rankThresholds` (RANKUP_NEED cumulative), rank lifts the soul-level cap (`SOUL_RANKS[r].cap` 10/20/30/50/100) and unlocks skills/passives. `level` grows via ✦Soul (EXP currency: `distributeBattleSoulExp` adds to each fielded primary job once per battle; `trainJob` spends ✦Soul at the altar). Stats `jobStatsOf` = base×5 × levelFactor × rarity × count-bonus (`SOUL_STAT_UP`: common1%/rare4%/epic10%/legend100% per soul). **控えの結社 (Order)**: `orderPassiveMap(party)` gives party-wide passives (`ORDER_PERK[k]` → goldLuck/senseEnemy/vigilance/…) from awakened jobs (rank≥2) **not** fielded as anyone's primary/sub — `partyPassiveLv` merges it, so every collected job matters even off-party. `recalcDoll(doll)` derives everything from `primary`+`subs`+SHARED. Soul drops roll a class by rarity (`rollJobClass` 70/20/9/1, `rollGreatJobClass` rare30/epic50/legend20); `acquireSoul` in game.js prompts strengthen-now vs take-home, banking uncommitted souls in `G.soulBag` (unlimited, auto-stored at the mansion, awakened into `G.souls` count there). Rank passives `PASSIVES`/`JOB_PASSIVES` (rank 2-5; hybrids removed). **Skill tables / 得意属性**: `JOB_SKILLS[k]` is written as a compact string per job via `T("1 KYOUGEKI 2 NERAIUCHI 5 extraHit/1 …")` (`Lv KEY` = skill, `Lv passiveKey/plv` = passive); each job keeps its own slot layout (skill count / levels unchanged by the 2026-10 skill overhaul), Lv40 = signature. `JOB_AFFINITY[k]` = each job's favoured elements (main, sub; shown as 得意属性 in the job codex sheet); the in-between levels 2/4/8/12/17/22/…/162 hold that element's physical skills or spells. The skill definitions live in **`src/skilldefs.js`** (`SPELLS`, re-exported by combat.js; header comment = full field vocabulary). Job identities: slow physical jobs get accuracy skills (`acc`: 狙い打ち → 心眼撃 → 必中 high tiers) and `pierce`; fast jobs get `agiScale`/multi-hit/crit, 盗む (`steal`), guaranteed escape (`kind:"escape"`); tanks get 挑発 (`taunt`) / 仁王立ち (`shield`) / 反撃の構え (`stance:"counter"`) and `vitScale`; casters/hexers get 毒 (`poison:{chance,pct}` = %maxHP per round, bosses half), 麻痺 (`para`), 特技封じ (`seal` → enemy can't use ability/role), 属性耐性ダウン (`vuln:{el|all: mult}` stored as effect stat `r_<el>`), 即死 (`instakill`, never bosses), 強化打ち消し (`strip`), 重力 (`gravity`), 目つぶし (`debuff:{hit}`); healers get リジェネ (`regen`), 弱体解除 (`purge`), MP譲渡 (`kind:"mana"`). Non-atk/vit/agi effects (seal/taunt/shield/ctr/charge/regen/hit/int/r_*) ride the same `effects` list (`_applyMod`, read with `Battle._bm`), so they tick and show as badges (`BUFF_KANJI` in game.js, `BUFF_NAME` in itemview.js). The elemental physical ladders keep their per-element rider (fire=power, water=AGI down, wind=multi-hit/AGI, earth=VIT down/flinch, light=HP drain, dark=MP drain/ATK down); 魔法剣 (`MAKEN_*`, `intScale`) lower that element's resistance. Run the headless sweep (every SPELL cast once + random battles) after changing skills. Keep all six elements covered by both physical and spell users when re-balancing.
- **`content.js`** — rank display definitions only (`RANK_NAME`/`RANK_COLOR`). The old procedural item generation (rank-prefix "二つ名" items) was removed in favor of `src/catalog/`.
- **`audio.js`** + **`src/music/`** — all music/SFX synthesized in code (no audio files). `src/music/`: `dsp.js`/`instruments.js` (sampled-at-init instruments: choir, strings, organ, brass, harp/lute, bells, piano, taiko/timpani, ambience…, generated in `worker.js` off the main thread with a main-thread fallback; `bank.js` caches/evicts them), `engine.js` (per-instrument channels, generated cathedral convolution reverb, tempo delay, compressor/limiter, crossfades, ducking under jingles, polyphony caps, pauses when hidden, `renderOffline()` for WAV previews), `score.js` (melody/chord/percussion notation with loop points and humanization), `songs.js` (the new themes: `title`/`opening`/`town`/facility themes/`layer1`/`battle*`/`boss*`, sharing the "soul motif" leitmotif), `legacy.js` (old step-sequencer themes for layers 2-20 re-voiced through the new instruments), `sfx.js` (layered SFX + orchestral jingles). Public API unchanged: `initAudio`, `setVolumes(bgm, sfx)`, `isMuted`/`toggleMute`, `SFX.*`, `playBgm(name)`/`stopBgm()`. Device prefs `dos-prefs` in localStorage (managed by `PREFS` in game.js — separate from the save, survives reset; also holds the vibration toggle read by `buzz`).
- **`title.js`** — title screen shown on every boot (`showTitle({hasSave, summary, onStart, onNewGame})`): cinematic animated scene (`titleart.js`: moonlit necropolis + labyrinth gate, recomposed per aspect ratio) + forged logo; first tap wakes it (unlocks audio → `title` BGM), then はじめから/つづきから. `onNewGame` (passed by game.js only when a save exists) confirms, then `newGameFromTitle` clears the save, sets `sessionStorage["dos-newgame"]` and reloads; `init()` sees the flag and skips the title straight into the opening. `init()` defers `resumeFromState()` / the opening until `onStart` (`startAfterTitle`), so nothing resumes behind the title.
- **`opening.js` / `openingart.js`** — the story intro `showOpening(done)`: 6 illustrated letterboxed scenes (slow camera, ink-bleed typewriter text, tap to advance, long-press/「スキップ」 to skip). Scenes are painted once while the screen is black between them. Scene 3「人業」 uses the user's illustration `art/op_dolls.png` (250×141 dots, drawn at an integer scale with a camera pan) with animated overlays (candle, moonbeam dust, the soul entering a doll; landmarks in `DOLLS_AT`). The 人業 design reference = wooden articulated dolls with blank spherical heads and dark steel joint bands. Text uses no `filter` on inline glyphs (iOS Safari leaves them blurred).
- **`pxpaint.js`** — shared pixel-painting helpers (shaded volumes, cloth, rim light, dithering) used by titleart/openingart.
- **`townart.js`** — town art rendered with a "relief raster" (per-pixel material/normal/depth → one key light + cold rim, dithered material ramps): `createTownScene()` (the animated night panorama of ロアダル at the top of the hub, with tappable landmark hotspots from `townSpots`), `vignetteCanvas(key)` (illustrated facility scene plates/header bands), `keeperCanvas(key)` (facility keeper busts shown in the keeper whisper row with a rotating line), `iconCanvas`, `KING_PORTRAIT` (story dialogue portrait, `{palette, art}`), `prewarmTown()` (bakes frames at idle time). The old `TOWN_ICONS` were removed. Hub/facility layout lives in `src/ui/` (see UI 構造; town portraits via `UI.partyPortraitCanvas`); styles in `town.css` / `ui-hub.css`.
- **`backdrops.js`** — per-layer battle backdrops: `drawBattleBackdrop(ctx, w, h, layer, now, {boss, elite})` paints the whole combat canvas background (static part cached per layer, cheap animated particles per frame). Called from `renderCombatCanvas`; `combatAnimLoop` in game.js redraws the combat canvas at ~20fps while waiting for input (particles, enemy idle bob, target ring).
- **`jobart.js`** — job character art converted from the user's ChatGPT images: `JOB_IMAGES[job][rank] = {palette, art, face}` (currently: all 6 basic jobs — fighter/knight/priest/mage/thief/bishop — plus samurai, berserker, hunter, shadow (暗殺者), paladin, guardian, spellblade, monk, hexer, hermit, brigand (義賊), arcthief (魔盗賊), crusader (聖戦士), battlemage (魔闘士), darkknight (魔騎士) & templar (神殿騎士), ranks 1-5; convert a job's rank variants with the same grid period so their height matches). `souls.js` `jobSprite` uses it when present (all jobs padded to one box `IMG_BOX` so they share scale; a missing rank borrows the nearest one — rank 1 dulled, 4-5 get a glow outline) and `jobBust`/`dollBust` crop a 36-dot head-and-shoulders square around `face` for small frames; since each job's art is drawn at a slightly different scale, `BUST_FIT[job] = {zoom, dx, dy}` widens/narrows (and re-centres) the crop and resamples it to 36 dots so every job's face reads the same size as the fighter's (zoom >1 = face drawn big, e.g. thief; <1 = small, e.g. hexer/hermit/arcthief) — tune it when adding a job's art. Draw portraits with `crispCanvas(spr, size)` (sprites.js: integer device-pixel scaling). Jobs without art keep the old 12×12 `JOB_ARTS`.
- **`walkerart.js`** — the player's board token: `WALKER = {down, up, left, right}` (20×31 red-hooded 操霊師, converted from the user's image; drawn at integer scale facing the move direction).
- **`crypt.js`** — the exploration board art: per-floor baked tomb-slab card backs (8 carved motifs + cracks/moss), flagstone floors with bones/candles/blood, cut-stone walls. game.js composites the baked layers and adds only the lantern light / fog of war / particles per frame. Board/HUD/battle-UI styles live in `dungeon.css`; party cards draw portraits via `partyPortrait(p)` (single switch point).

### 🔒 公開範囲 = 第1〜3層 (作り込み中の縦切り)
The game is being rebuilt as a polished **vertical slice, one layer at a time**: layer 1 (opening → town → dungeons 1-5 → layer boss) **layer 2「地下水路」(dungeons 6-10)** and **layer 3「廃坑」(dungeons 11-15)** are open. Milestone feature unlocks (魂融合 D5 / サブ魂 D10 / 酒場の噂 D15 / 結社 D20 / 納品枠) count **reported** dungeons (`reportedDungeonCount` → `featureUnlocked`/`unlockedSubSlots`/`orderSeats`/`deliveryQuestCap`), so a feature opens only after the king's report plays its UNLOCKS page — not on clearing the dungeon. While `G.msq.state === "report"` the gate is closed until the king hears the report (`reportPending`/`blockForReport` in game.js, checked by `openDeparture`/`departNow`/`departAbyss`). `CONTENT_LIMIT = 15` in game.js: dungeons beyond it are "準備中" (hidden from the town list, `tryEnterDungeon` refuses, the abyss is closed). After the report of the last open dungeon, `acceptMainQuest` sets `G.msq.state = "sealed"` and the king announces the next layer is sealed (`sealedLines()` ← `SEAL_LINES[last open layer]` in `story.js`); `contentSealed()` drives the palace/objective UI (texts are layer-generic). Existing saves that are already deeper keep their `G.msq` untouched (only display/entry is blocked).
**To open the next layer once it is polished:** raise `CONTENT_LIMIT` by 5 and add `SEAL_LINES[new last layer]` + `UNSEAL_LINES[newly opened layer]` in `story.js`. Saves sitting in `"sealed"` are migrated in `loadGame` to `"offer"` with `msq.unsealed = true`; `acceptPages` then plays the 「封印の解かれた門」 page before the new layer's decree.
**Per-layer polish checklist** (what layers 2 and 3 got): themed dungeon names (`DUNGEON_NAMES` in generator.js), a roster that starts above the previous layer (`LAYER_POOLS` — no lower-rank stragglers), per-layer elites (`LAYER_ELITES` in bestiary.js; `eliteKey` cycles them by floor and falls back to the old 10-dungeon `ELITE_ORDER` for layers without an entry), showcase SR16/LR8 (`catalog/layerN.js`), Irene lines, and the seal/unseal lines. Layer 2's 23 monsters (20 regulars + boss + 2 elites) have hand-built `hd_*` HD prototypes like layer 1 (see **Layer 1-2 HD monster art** below); layer 3's art is still a placeholder awaiting the user's illustrations (see **Monster art swap** below).

### 装備のレア度 (5段階) — `src/rarity.js`
Every equipment item has `rar`: `c` コモン(白) / `uc` アンコモン(緑) / `r` レア(青) / `sr` スーパーレア(橙) / `lr` レジェンドレア(赤). **Names are colored by rarity everywhere** (`itemNameEl` / `.rar-*` classes; unidentified items still show the color). Classification is assigned in `catalog/index.js` from the source: rank-file standard gear → lower-lv of each pair `c`, higher `uc`; unique one-offs (weapons/armor/gear.js) → `r` (stats ×`RARE_STAT_MUL`); exclusives `x_` + legends → `sr`; `lr_` → `lr`; per-layer showcase items (`catalog/layer1.js`, `layer2.js`, `layer3.js`) carry their own `sr`/`lr` **and `layer`** — `pickOfRarity` skips items whose `layer` is deeper than the current `battleLayer()`, and `lrPool` admits tier 1-4 LR (`lr` = its layer) only from that layer on and within `lootCapR`. Layer-2 water enemies are best resisted by **earth** `eDef` (defense must *beat* the attack element — a same-element eDef does nothing); layer-3 earth enemies likewise by **wind** (`layer3.js` leans on wind eAtk/eDef). Base items.js gear defaults to `c` (game.js after the ITEMS merge).
- **Drop pipeline** (`pickLoot(opts)` in game.js; all loot goes through it): 8% collectible, else **LR time roll**, else `rollRarity(rarityUp(opts))` then `pickOfRarity` from the R window (centerR ±2, widening, then downgrading). **Base R = `lootBaseR()` = `ceil(cfg.lootLv[1]/10)` (= the layer: D1-5 → R1 … D96-100 → R20; extra dungeons / the abyss only need a `lootLv`).** Modifiers (elite/rare/chest rank/mimic/special floor/mutator) push the center up, but center and window are hard-capped at **`lootCapR()` = base + `LOOT_R_HEADROOM` (2)** — layer 1 never drops gear above R3 (lv30); tier-1 LR are gated by the same cap. (R used to be the dungeon number, which let D5 drop R3-7 gear and trivialized layer 1 — don't key loot on `dungeonNumber`.) `rarityUp` = chest rank / elite / mimic / black chest / special floor / mutator **+ depth (`layerRarityUp`)**. Items usable by someone in the party are weighted ×3.
- **Curated drop pools ("少数精鋭")**: C〜R items flagged `noDrop` in `catalog/index.js` are excluded from drops (not deleted — still in catalog/codex/saves): 1 standard item per band per slot-type (C/UC alternating), `RARE_PER_BAND` uniques per band. SR/LR are untouched. Keep this when adding items: new commons/uncommons should replace, not pile up.
- **LR is time-based, not per-drop**: `G.lrClock = {since, pend}` accumulates *active* play time (visible + input within 2 min) × `lrLayerFactor(layer)` (layer 1 ≈ 0.02 → LR almost never drops in layer 1). At each equipment drop, `p = 1 - exp(-pend / (M × LR_HAZARD_K))` with pity at `M × LR_PITY_K`, where `M = lrIntervalH(dungeonNumber)` = 5h up to D15 → 4h at D33 → 3h from D50 (cap). LR are 1点もの (`G.lrOwned`, marked in `runGainItem`); `refundLR` restores the pity if an LR couldn't be carried. The old flat-2% exclusive layer was removed.
- Appraisal cost = sell price × `APPRAISE_MUL[rar]` (deep job-LR tier≥5 still ×20). Bulk sell skips SR/LR and undonated collectibles (`sellWarnings`).
- Owned items are re-synced to the catalog on load (`reflattenItemStats`: stats/art/rar/etc. from `ITEMS[id]`, instance flags like `unidentified` kept).

### Dungeon registry (`src/dungeons/`) — generated dungeons + rank-tiered bestiary
- **`schema.js`** — shared definitions: `defMonster`/`defMonsters` (validates `artKey`, applies `palette`/`tint`, fills defaults), `ARTS` art prototypes, `MON_RACES`/`RACE_LABEL`, **`monStats(rank, boss)`** (the single balance point: rank 1-10 → hp/atk/def/spd/soul/gold curves), and the **element system** (`ELEMENTS`, `elemBeats`, `elemMult`).
- **`bestiary.js`** — ALL monsters, organized by **rank 1-10**. Legacy monsters (`cm_*`, `d01_*`…`d04_*`, defined in `common.js`/`d01.js`…`d04.js`, ids preserved) are rank-remapped and re-statted via `monStats` at load; new monsters use the `bs_` prefix. Exports `BESTIARY` (id→def), `RANK_POOLS` (rank→{regular, boss}), and **`BOSS_ORDER`** (rank → ordered list of 10 boss ids; dungeon n gets `BOSS_ORDER[rank][(n-1)%10]`, so **all 100 dungeons have a unique boss**). Throws if any rank 1-10 lacks regulars, lacks a boss, or has a malformed `BOSS_ORDER` row. Don't reorder `BOSS_ORDER` entries — that silently reassigns which dungeon a boss belongs to.
- **`generator.js`** — generates all **100 dungeon configs** deterministically from the dungeon number n (1-100): rank = `ceil(n/10)`, name from a fixed 100-entry table, regular pools rotate through `RANK_POOLS`, boss = `BOSS_ORDER[rank][(n-1)%10]`, `enemyScale` ramps 0.7→1.7 within each 10-dungeon band, `lootLv = [n*1.5, n*2]`, `rankBonus` is logarithmic (legend souls stay ~3.6% even at n=100), `soulLevelBonus = floor((√n-1)*1.6)`.
- **`index.js`** — the aggregation window: re-exports `DUNGEONS` (from generator) and `DUNGEON_MONSTERS` (= `BESTIARY`).
- **`d01.js`…`d04.js`/`common.js`** — kept only as monster-definition sources for bestiary.js; their `dungeon` config exports are no longer used.

**Conventions when adding content here:**
- Monster IDs are **namespaced** (`bs_troll`, `cm_slime`) and treated as **append-only** — IDs are persisted in saves and codex, so renaming/removing them breaks existing saves. Add new IDs rather than repurposing old ones.
- **Adding a monster = append one entry to `bestiary.js` with a `rank` (1-10).** It automatically appears in every dungeon of that rank band. Don't hand-write hp/atk — stats come from `monStats`.
- Every monster needs a valid `artKey` (one of `ARTS`) — `defMonster` throws otherwise. See **Monster individuation** below for the unique-design rule.
- **Layer 1-2 HD monster art (`hd_*` in `schema.js` ARTS)**: layers 1 and 2 use hand-built high-res prototypes (regulars 96×96, layer boss/elites 112×128; dark low-key ramps, upper-left key light, no outline — shadow-side edge is the darkest tone, cold rim on the back edge, `o` = pure black for sockets/mouths). Layer 2's 23 are generated by **`tools/hdart/`**: a small SDF ray-marcher (`sdf.mjs`: sphere/ellipsoid/cone/tube/box/slab/cyl/torus + smooth union/sub/displace/paint, soft shadows, AO, point lights, Bayer-dithered ramps, inner depth lines, rim) plus 2D finishing passes (teeth via `fangs`, drips, particles). One script per monster in `tools/hdart/layerN/<name>.mjs` (`meta = {id, key, w, h, note}`, `build()` → `{palette, art}`). `node tools/hdart/run.mjs layer2 [names]` renders a preview PNG (view it — check silhouette/readability, not just numbers); `--apply` rewrites that layer's `hd_*` block in `schema.js` and the `artKey`s in `bestiary.js`/`d0x.js`. For a new layer add its `HEAD` entry in `integrate.mjs`, then bump `sw.js`.
- **Monster art swap (`src/dungeons/monart.js`)**: `MONSTER_ART[id] = {palette, art}` overrides just the sprite of that monster id (battle/board/codex) after `BESTIARY` is built — ids/stats/traits untouched, validated by `validateMonsterArt`. `ART_WANTED[layer]` lists ids awaiting the user's illustrations (layer 3: 20 regulars + boss + 2 elites; layer 2 was done as `hd_*` prototypes instead). Convert a PNG with `node tools/monart.mjs <id> <image.png> [--h 96] [--colors 16] [--preview]`, or a whole folder of `<id>.png` with `node tools/monart.mjs --dir <folder> --layer 3` (boss/elite default height 120, others 96); `--list 3` prints the layer's wanted ids with names and swap status (built-in Node only: background flood-removal from the corners, area-average downscale = 1 dot per pixel, median-cut palette; rewrites the `<<MONSTER_ART>>` block). Then bump `sw.js`.

### Monster individuation (固有デザイン・特徴・スキル) — the per-monster identity rules
The goal (per design direction): **every enemy is individually distinctive**, both visually and mechanically. Two rules enforce this — apply them whenever adding or refining a monster.

**Rule 1 — unique art per monster (no palette-swap clones).** Each monster gets its **own `ARTS` prototype**. Do *not* differentiate two monsters by `palette`/`tint` alone (e.g. a green-tinted `kobold` for a goblin) — that reads as a recolor, not a design. `palette`/`tint` is acceptable only for *minor* variants of the *same creature concept*, never to dress up a different creature. Authoring workflow for a new prototype:
  1. Add a `{ palette, art }` entry to `ARTS` in `schema.js`. `art` is an array of rows (variable row length allowed — right side is padded transparent; `.` = transparent). Convention: `o` = outline (darkest), light source upper-left, ~3 tones per material. Resolution may be mixed (old 12×12 / new ~16-32px); `drawSpriteFit` normalizes display size.
  2. **Verify the silhouette before committing** — you can't see a canvas headlessly, so render an ASCII preview: map each non-`.` glyph to a block (`o`→`##`, others→glyph×2) and print the grid. Iterate until the shape reads clearly and is distinct from its neighbours.
  3. Set the monster's `artKey` to the new prototype and **remove any `palette`/`tint` override** so it uses the prototype's own palette.
  4. Check for clones: no two monsters in the same dungeon band should share a prototype. (Quick check: import `BESTIARY`, group the roster by `m.art` signature, flag any group >1.)

**Rule 2 — give each monster a distinctive combat trait (TRAITS).** `schema.js` defines `TRAITS` (the shared vocabulary) and `monsterTraits(m)` / `monsterTraitKeys(m)` (normalize a def's fields into an ordered trait list). The monster codex shows these traits (固有ドロップ was abolished — see below). Author traits on the def via:
  - **`ability`** (single special action, used ~25-30% of turns by `combat.js` `enemyAct`): `poison` / `paralyze` / `stone` / `drain` / `soulSteal` / `goldSteal` / `critical` / `breath`. Set explicitly to override the race-default auto-assignment in `game.js` (`RACE_ABILITY`); set `ability: null` to suppress it. **Brutal abilities (`drain`/`soulSteal`/`critical`/`stone`) are gated to rank ≥4** — don't put them on low-rank enemies.
  - **`role`** (`summoner` + `summonKey` calls allies mid-battle / `healer` heals wounded allies / `guard` + optional `escort` body-blocks). Solo bosses can use `summoner` (spawns adds) but `healer` is wasted on a solo boss.
  - **Passive combat fields** (read by `combat.js` `makeEnemy`/`_physical`/`_cast`/`_startRound` and `spawnCardEnemies`): `physResist` / `magResist` (**耐性ランク 1-3** — `RESIST_RATE` in schema.js: 1 = 50%軽減「効きにくい」, 2 = 75%「ほとんど効かない」, 3 = 100%「無効」; `defMonster` throws on anything but 1/2/3, on rank 3 for bosses/elites, and on dual phys+mag resist above 2, so every enemy stays killable; `monsterTraits` shows 「物理耐性N」+ the rank text; immune hits return `immune:true`/0 dmg, show 「無効」, and auto combat skips/stops on phys-immune foes. Depth curve: layers 1-5 mostly rank 1 (rank 2 rare), mid layers mostly 2, rank 3 from layer 9 and common from layer 15 — keep that curve when authoring), `magWeak` (>1, attack-spell damage multiplier — "魔法に弱い"), `regen` (0–1, self-heal per round), `swift` (bumps AGI +4), `evasive` (+15% physical dodge), `pack` (spawns ≥3). `defMonster` whitelists these — add new fields there *and* to `monsterTraitKeys` if you introduce more.
  - Aim for a **1-2 trait headline** per monster that matches its flavor text, and keep traits varied across a band (don't make every rank-1 enemy poison). The touchstone examples: the "物理耐性 + 魔法弱点" slime, the "招来" rat-caller, the "ブレス" dragon (rank ≥6).

**固有ドロップは廃止 (drop system removed).** Monsters no longer carry `dropNormal`/`dropRare`. Post-victory chests roll generic loot from the dungeon's `lootLv` band (`rollGenericDrop` in `game.js`). The codex "落とすもの" panel was replaced by a "特徴・スキル" panel driven by `monsterTraits`. Don't re-introduce per-monster drop tables.

**Progress:** **All ranks 1-10 are fully individuated** — every monster (regular/role/boss/elite) has a hand-tuned trait headline and a concept-appropriate sprite. New prototypes were authored to fix concept mismatches (a different creature wearing another's silhouette): rank 1 `caverat`; rank 2 `soldier`/`zombie`/`gnoll`/`hound`/`gobshaman`/`piper`/`gobchief`; rank 3 `werewolf`/`scorpion`/`darkelf`; rank 4 `gargoyle`/`gorgon`/`deepsahagin`/`banshee`/`cultist`/`samurai`; rank 5 `dullahan`/`ironknight`/`fireserpent`; rank 6 `stormgiant`/`wyvern`; rank 7 `vampire`/`reaper` (+ `stormwyvern` reuses `wyvern`); rank 8 `crystalgolem`/`necromancer`; rank 9 `angel` (+ `soulreaper` reuses `reaper`); rank 10 (`primalserpent` reuses `fireserpent`). Brutal abilities (`critical`/`drain`/`soulSteal`/`stone`) are only on rank ≥4. Remaining shared prototypes are intentional **same-concept tint variants** (e.g. two orcs, two armored knights, lich/ghost/skeleton/mandrake/ogre/dragon/imp families, bosses-in-different-dungeons) — consistent with the accepted bar. When **adding new monsters**, keep this bar: give a concept-mismatched newcomer its own `ARTS` prototype (don't recolor an unrelated one) and a hand-tuned trait. Note: elite (`el_*`) monsters carry `rank = band+2` but spawn in the lower band's dungeons (an elite of `rank R` appears in `rank R-2` dungeons), so group by spawn-dungeon, not `.rank`, when checking co-appearance. A few single-in-band creatures still ride a related-concept prototype by choice (e.g. `chimera`/`griffon`/`naga`/`godslayer` on beast/harpy/sahagin/orc) — fine as accepted variants, but candidates if a future pass wants even tighter individuation.

### Item catalog (`src/catalog/`) — unique items, additive-by-design
- **`defs.js`** — shared item `ARTS` (12x12 shapes per weapon subcategory / armor type / misc trinket) and builders `W/S/A/H/F/G/R/M/U` (weapon/shield/body/head/feet/hands/accessory/misc/usable). Builders derive atk/def/price/rank from the hidden item level and validate input (throw on bad cat/shape/lv/desc).
- **`weapons.js`/`armor.js`/`gear.js`/`misc.js`/`legends.js`** — the hand-written unique-item catalogs (100 weapons, 50 shields, 50 body, 50 head, 50 feet, 18 hands, 8 accessories, **100 収集品/collectible loot (exactly 10 per rank band R1-R10, grouped by `ceil(lv/20)`)**, a few potions, plus 11 mythic legends at lv165-200). **`index.js`** merges them into `CATALOG_ITEMS` (throws on duplicate IDs); `game.js` does `Object.assign(ITEMS, CATALOG_ITEMS)` at load.
- Item IDs are prefixed (`w_`/`s_`/`a_`/`h_`/`f_`/`g_`/`r_`/`m_`/`u_`) and **append-only** (saves/codex reference them). Names are unique one-offs — there are no rank-prefix "二つ名" items anymore.
- Every item has a **hidden level `lv` (1-200)** matching the 100-dungeon `lootLv` bands (lv1-20 = mundane gear, 165-200 = mythic): dungeons define a `lootLv: [min, max]` band (interpolated by floor depth) and `game.js` rolls loot with a gaussian window around that center plus a global decay, so higher-lv items are rarer everywhere. Post-victory loot is rolled generically from the current dungeon's `lootLv` band (`rollGenericDrop`; per-monster 固有ドロップ was removed). Display rank (R1-R6) derives from lv via `lvToRank` (thresholds 20/45/80/120/165). When adding items, keep every ~20-lv bucket populated or loot rolls in that band degrade to the `herb` fallback.
- Slot `misc` (収集品: collectible loot) can't be equipped or used; collectibles are either sold at the shop or **奉納 (donated) at the 王宮 宝物庫 (treasury)**. The old `mat`/貴重品 slot (空の魂) was removed. The treasury (`renderTreasury` in `ui/palace.js`) has **no collectible ranks and never reveals the total number of kinds**: the 奉納台帳 lists only donated items as codex-style cards (like the item codex), and only the **next** unclaimed milestone (`TREASURY_MILESTONES`, by total donated kinds) is shown. All held collectibles are donatable (`opsDonatableList` → `{doll, item, dup, gold}`): a new kind is recorded in `G.treasury.donated`, while an already-donated kind (or a 2nd copy) is consumed for its sell price in gold (`donateCollectible`). Badges/suggestions count only new kinds (`counts.donatable`). Rewards claimed are tracked in `G.treasury = {donated, claimed}`.

IDs are `*_rN_*` and append-only. `index.js` merges `RANKn_ITEMS` like the rest. **Status: R1-R20 全完了** (`r01.js`…`r20.js`, 計880点, all registered in `index.js`). - **Armor stat philosophy by weight (= job archetype):** 足(feet) = AGI部位 for all weights (auto `F` builder, `FEET_AGI_COEF` cloth>light>heavy). 頭(head): 物理職(軽/重)=VIT, 術者(布)=INT or PIE. 小手(hands): 物理職(軽/重)=ATK (攻めの部位), 術者(布)=INT or PIE. #### LR (レジェンドレア・専用装備) — `src/catalog/lr.js`, id prefix `lr_`
- **Job-exclusive equipment, ~5 ranks above its drop band** (LR5 ≒ display-rank R10 power; tiers LR5/LR10/LR15/LR20 via the `lr` field). Anchor: warrior LR5 「フランベルジュ」 ls ATK +90; other categories scale by `W_MUL` (ls90/dg70/kt95/ax104/mc99/sp94/bw83/st auto). ### Element / affinity system
Six elements + `none`, defined in `schema.js`. Advantage cycle is **火→風→土→水→火** (fire→wind→earth→water→fire); **light↔dark are mutually advantageous**. Offensive spells carry an `element`, enemies carry `element` from their monster def.

**Elemental attack/defense stats (属性攻撃/属性防御):** items can carry `eAtk`/`eDef` (`{el, lv}`); `recalc` aggregates them per member into `member.elemAtk`/`member.elemDef` (same element stacks, capped at Lv2=◎; different elements don't mix — strongest wins). `elemDmgMult(aE, aLv, tgtElem, tgtDef)` in `schema.js` is the single damage-multiplier entry point used by `combat.js` (`_physical` and the `atk`-spell branch): the attack side compares the attack element vs the target's innate element (Lv1=◯ ±50%, Lv2=◎ ±100%), the defense side compares the defender's `elemDef` vs the incoming attack element (**reduction only** — when the defense element has the advantage it cuts damage by 25% (Lv1) / 50% (Lv2), but a disadvantageous element never increases incoming damage). Spells act as Lv1 unless the caster's `elemAtk` matches the spell element. The legacy flat `elemMult` remains for reference but combat uses `elemDmgMult`.

### State & persistence
- All runtime state hangs off the single global `G` in `game.js`. `state` field switches the active screen (`town`/`board`/`battle`/`over`).
- Save key: `dos-save-v4` in `localStorage` (v1-v3 saves are intentionally orphaned — v4 made souls a party-shared pool with vessel dolls, primary+sub-soul slots, and the Order). Only the fields in `SAVE_FIELDS` are persisted (transient animation state is excluded).
- Saving uses **`refSerialize`/ref-hydrate**: a custom serializer that encodes shared/circular object references as `{$r: index}` so object **identity is preserved** on load (a single soul object referenced from multiple places stays the same instance). When adding state that relies on shared references, keep it inside this graph rather than re-cloning.
